# Studio 项目设置与文件整理

2026-10-14，第八阶段开发收口。独立Runner及组件下载仍后置；不改项目格式、安装身份或旧数据，不自动授予系统权限。

## 设置保存

- 新建Studio可视化项目继续从当前生成积木目录收集默认能力。打开旧项目不补选能力，清单里的未知能力继续展示和保留。
- 能力、运行延迟、提示总开关/筛选、弹窗样式及随机策略统一编辑，一次调用既有 `updateExecutionSettings` 保存。日志的两个记录开关仍从日志记录设置单独维护。
- 本次将三份跟随清单重建的草稿改为同一编辑基线。资源导入/预览刷新不会替换未保存内容；其他操作改变能力或运行配置时，脏草稿保留并显示冲突，不用最新基线覆盖旧草稿保存。
- “重新读取”真实读取正式项目，未保存时先确认丢弃。清洁草稿可以跟随外部已保存设置，脏草稿不自动合并。保存仍由存储层复核原始能力/调试/随机配置，冲突不写入部分修改。
- 窗口按项目身份隔离，异步保存、资源导入/删除和高级界面保存透传取消，finally释放忙状态；冻结资源目标、目录和保存期望值，迟到结果不进入新项目。
- 高级界面JSON继续保留真实入口与校验，明确区别于右侧可视化设计器。取消/关闭存在未保存文本时确认，不把高级数据编辑当作新的源码项目。
- 移除项目设置里的重复系统权限/Root入口，系统权限及运行环境从“我的”进入；本窗只维护脚本工程配置。自动变量提示按插件显示名称选择作用域，内部 `flow:<id>` 不变。

## 文件语义与边界

项目是完整脚本工程，插件是独立流程文件，主插件是项目启动入口。分组是虚拟分类，图片目录是真实资源目录；变量和界面仍在清单，运行日志和编辑恢复记录仍在私有目录且不进入项目备份。详见[项目组织](project-plugin-organization.md)与[项目存储](project-data-storage.md)。

本批修正残留“源文件不存在/未调用源文件”提示和变量类型“寻图”标签，统一为插件/图像；不改 `flowId`、JSONL、编译器节点或API。

## 清理原则

移除只有测试引用的退役“缩小全部75%”实现、无调用的布局壳、重复调试分支以及AI模拟发送/附件/会话配置。AI路由保留为真实的“尚未开放”说明，不生成模拟结果。文件管理兼容面板、共享参数适配、只读API文档、Lua历史工程/协议及备份读取继续保留，不能仅因名称旧就删除。

改前混合源码已有本地快照，恢复方法及本次清理明细见[清理记录](../verification/studio-settings-cleanup-2026-10-14.md)。没有删除用户项目、图片、参考源码、截图、模型、原生库、ADR或现有历史证据。本批不搬动整个模块，不新增参与构建的归档源码目录。

## 验证边界

新增用例覆盖脏草稿保留、外部设置冲突、资源刷新、显式重新读取、项目会话、非法对齐值及退役入口约束。只编译源码和测试源码，执行测试、Lint、APK打包与安装继续后置；不以历史批次测试数或构建结果冒充本批验收。
