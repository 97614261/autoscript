# 运行文件日志与识图效率分析

入口：可视化编辑器底部「日志」→「实时 / 历史」。默认显示开始、暂停、继续、完成/停止、脚本主动输出和错误；列表按时间、类型、内容排列，支持全部、输出、错误筛选、跟随、搜索及点击查看/复制完整原文。实时只保留最近200条，历史按运行区分；手动刷新可读运行中的已写记录。

「更多」提供内部诊断、识图性能统计、记录设置、刷新及错误定位；历史另有观测原文、导出和确认清理。普通 Runner / Root / App 状态不进入默认列表，真实故障仍可见。开启「逐积木执行记录」后显示真实进入事件，未开启时不根据高亮补造过程；循环可能产生较多记录。新运行显示“插件 放技能 · 第 12 行 · 点击”，失败追加“执行失败”；名称和行号来自当次运行的检查点，不随后续改名、增删或折叠改变。内部编号保留在详情、复制原文和导出中，旧记录缺少信息时明确说明，不凭当前草稿猜测。历史脚本视图合并原脚本文件和观测文件中的执行身份、位置名称、任务失败及丢失计数，不自动记录源码、变量值或模板路径。

系统文件选择器导出文本，不自动上传。最近16次运行，脚本与状态通道各1MiB；新事件最多8段、每段256KiB，条件表最多256项且256KiB。超限明确显示队列丢弃、通道限额或明细轮转计数。目录为 App 私有 `files/runtime-logs/<运行 UUID>/`，一般文件管理器不可直接访问。

日志弹窗使用有界紧凑布局，历史单行选择。识图统计按精确配置收成卡片，截图总耗时及三个分段在同一卡片用「耗时项 / 次数 / P50 / P95 / P99」表格显示；长积木 ID、ROI、模板尺寸等仅在详情展开。不同节点、输入参数、后端和结果类别继续独立计数，展开/收起不改变数据或导出内容。

2026-10-14，第六阶段补强：实时日志使用不可变快照刷新，支持全部/脚本输出/运行诊断/其他筛选；未知旧格式不丢弃，ERROR 级日志能进入“仅错误”。实时/历史列表默认两行摘要，点击可查看完整原文、全屏与复制，不改文件内容。调试草稿和提示清理规则见[Studio调试与提示](studio-debug-and-prompts.md)；本批测试执行及安装后置，不引用历史验收作为本批结果。

日志标题右侧固定方框按钮支持「全屏 / 还原」，适用于 App 内及系统悬浮编辑窗，不放在滚动操作区。全屏填满可用区域，保留系统安全边距、关闭和返回操作，取消底部重复关闭栏。全屏/还原不重新读取日志、不清空筛选或选中运行；统计使用约 18 dp 单行、每种结果独立表头，不再逐行重复“找到”。卡片「详情」展开数值，「参数/口径」再展开长 ID 和说明；全屏也保留滚动，任意数量的条件和系统大字体不能保证一屏放完。

统计页「更多」提供两次运行对比和截图统计总览；历史及统计的「更多」提供导出完整日志。实时页可复制筛选结果。「同记录条件对比」窗口支持右上角全屏/还原，切换不重新读取对照数据。

需要一次截图时，在「识图统计」点上方工具条「截图总览」，自动进入全屏紧凑表格。默认选择首个识图条件，保留全部数值、各行实际样本数和P50/P95/P99；同插件、积木和帧尺寸只有一个截图条件时，附上独立截图统计，不把两者合并成整轮百分位。条件下拉可单独切换截图或识图；不同截图后端/传输条件有多个时不自动选择其中一个。小屏、大字体或多结果状态明确分页，续页重复结果标题，既不删指标也不混合结果。对比、截图总览/详情及总览导出位于工具条，不再挤占标题和全屏按钮。先前720×1280、默认字体核对能显示的指标数属于历史布局证据，本次布局未做设备像素视觉验收，不承诺任意数据量一页。

预筛排除率按每条事件的 rejected/candidates 计算后取百分位，零候选无比率样本；不拿两个计数的百分位相除，也不合并不同结果或输入。次数仍表示该行实际有效样本数，整数工作量、百分比与毫秒分别格式化。表数量现可为 0（首候选已经找到）、1 或 2，构表像素预算随实际表数计数，不伪装为单表。

日志 → 记录设置：

独立紧凑小窗只提供「积木执行追踪」和「识图耗时统计」两个真实开关，并展示自动记录范围和隐私提醒。默认高度按内容收起，窄窗/大字体可滚动。显式保存后生效；取消、关闭或返回存在未保存修改时要求确认。只更新这两个字段，保留最新运行延迟、提示总开关、提示筛选和弹窗样式，不修改现有日志。

- 文件日志自动记录脚本主动 Log 输出和安全的 Runner 状态；不自动保存用户 Lua 源码、变量快照、识别出的文字、模板路径和截图。完整原始错误仍可在错误弹窗主动复制。
- 积木执行追踪默认关闭，打开后记录进入检查点的插件/积木 ID、插件名、积木行号/名称及任务终止状态；不是每个积木的完整执行耗时。旧生成物无显示信息时保留身份，不补造名称和行号。
- 带中文、路径符号或非规范文本的历史 ID 在观测中使用匿名指纹，不能因新增日志而拒绝原本有效的脚本；真实持久化身份及源码映射不变。匿名指纹仅用于本构建的排查，不作为跨版本永久身份。
- 识图耗时统计默认开启，可关闭；改变设置后需保存并重新运行。Studio 与导出的独立 Runner 冻结同一配置。老项目缺失字段默认不开追踪、开启指标，不删除旧数据。

## 能分析什么

2026-10-09紧凑日志：同一识图条件存入 `conditions.jsonl` 一次，各次观测在 `events.<20位序号>.jsonl` 写条件引用和数值数组，最多保留最近8段；旧 `events.jsonl` 可读且不自动删除。文件格式为版本2，JNI/引擎观测仍为版本1。无法无损编码或条件表达到预算时回退完整事件，不删除未知字段。历史“追踪/指标”显示短摘要，导出保留完整条件和紧凑数值，统计解码后沿用相同单位和分组。布局及源码/变量/图片隐私规则不变。

元数据中的 `visionCaptures/visionFound/visionNotFound/visionFailed/visionCancelled/visionEngineDropped` 是写盘线程已经处理的累计观测，不受明细轮转影响，但不能补造引擎或待写队列丢失的样本。旧日志无这些字段时从保留明细计算；存在丢弃或无效仍注明观测不完整。`evictedEventRecords` 统计轮转淘汰的旧明细，页面明确提示：顶部次数为累计，表内次数和P50/P95/P99仅覆盖当前保留窗口，不声称整次运行百分位。停止尾部与最新错误可继续入段，不再因为最初单文件写满而一直拒绝后续事件。详见 ADR 0051。

2026-10-09：运行总览增加单调时钟观测的 `durationMs` 和从实际认证完成起算的 `rootSessionAgeMs`。运行中显示“已记录”，它是最后一次写入的观测快照，不是每秒刷新的计时器或通道健康证明；终止时更新最终时长。原认证会话中断后记录 `rootSessionChanged=true`，冻结旧会话年龄并标记“已断开”，不将重连时间拼接进去。旧日志缺项显示未知，不能从样本数或墙上时钟推造运行时长。主操作计数只统计截图总事件和识别结果，不重复计入分段/工作量行；丢弃、限额和无效记录仍单独标明。

新端协商成功后增加完整可选对象 `captureTransferUs`：`sendEncode` 为数据包封包/鉴权，`sendWrite` 为写出/背压，`receiveRead` 为像素包接收等待/读取，`verify` 为像素包验签/协议校验，`append` 为像素追加，前五项单位微秒；`packets` 为像素数据包数量，单位个。发送端数值由固定25字节认证结束摘要传递，客户端校验关联、序号、包数及数值范围，异常作废连接而不使用已接收帧。旧端不补零。发送与接收并发，接收细分不含结束摘要等待，不能将分段或百分位相加解释总耗时。截图总览默认保留原主指标，在条件栏切换“传输明细”单独查看这六行，避免把新增指标塞入原截图页。

`CAPTURE_CONTROL_UNAVAILABLE` 明确表示优先停止通道失效触发安全清理，区别于 `CAPTURE_BACKEND_FAILED` 的采集后端失败；新原因仅按可选能力协商传递，旧端仍保留原失败格式。回归与本机帧入池对照见 [本批交付记录](../../archive/project-history/2026-10-10/docs/run-health-and-capture-transfer-delivery.md)。

捕获设备/Android API/ABI/屏幕大小；匹配逐条记录帧尺寸、ROI、模板数量及尺寸、容差、相似度、搜索方向/结果上限、耗时及结果。模板维度为 [0,0] 或帧尺寸缺失意味着输入未成功解析，不可用于几何基准。截图返回成功后记录实际捕获帧尺寸；分辨率变化的样本分组独立。

`capture-host-roundtrip` 是截图宿主往返耗时，包含等待调度、后端截图及回复，不能称为纯截图内核耗时。`rust-rgba-*` 不含截图，但含当前匹配调用的校验与结果编码；OpenCV/ONNX 指标也包含宿主往返。暂停期间等待的宿主请求同样计入观测时间，做正式基准请不要混入人工暂停。

快速截图链路另外记录 `captureStagesUs`：`acquisition` 是后端采集及桥管道读取，`transferVerified` 是元数据接收后到全部像素包验证完成，`framePublish` 是像素转入共享帧池。界面分别显示「截图采集（含桥读取）」「帧传输 / 鉴权」「帧入池」。它们不覆盖全部调度和元数据开销，不能将各段 P50/P95/P99 相加当成整轮百分位。`captureBackend` 区分 `root-surfacecontrol` 常驻桥和 `root-screencap-fallback` 兼容后端；不同后端/传输方式独立分组。旧端继续记录总耗时，缺失分段不是零耗时。详见 [快速截图与等价预筛](../../archive/project-history/2026-10-10/docs/fast-root-capture-optimization.md)。

P50/P95/P99 使用最近秩定义 ceil(N×p)；只聚合同积木、算法、帧/ROI/模板尺寸、阈值、方向/上限和同结果类别。找到与未找到分开，取消、超时、预算超限、错误独立。模板名称/内容不进入统计；若通过动态代码改变模板内容，仍需人工固定同一模板再比较。样本量少时只能排查，不能断言性能提升百分比。存在任一丢弃/无效计数时注明非完整观测。并发任务指标按完成事件保留，不以文件写入时刻代替算法耗时。

2026-10-09：Rust 单模板、模板列表首结果、多结果匹配新增可选 `matchStagesUs` 和 `matchWork`，在「详情」展开，默认视图保持紧凑。阶段单位为微秒，页面转换成毫秒：

- `setup`（准备 / 收尾）：整次调用扣除下述阶段的残差，包括参数解析、校验、帧池锁等待、模板准备及结果封装；不是独立测得的磁盘读取时间。
- `prefilterBuild`（预筛构建）：创建或检查必要条件积分表的阶段耗时。
- `searchCompare`（遍历 / 精确比较）：校验、候选遍历和精确比较合计，不是单独逐像素 CPU 时间。

`matchWork` 为工作量，不是耗时；页面百分位不除以 1000。`templatesVisited` 是访问模板数，`preparedCacheHits` 是已有预处理复用次数，`templatesPrepared` 是现场预处理次数，`prefiltersBuilt` 是完成构建的积分表数，`candidatesVisited` 是访问候选数，`prefilterRejected` 是判定排除数，`comparisonPixels` 是精确比较实际消耗的像素预算（含锚点），`prefilterWork` 仅是构建积分表消耗的像素预算。预筛排除候选另消耗一个预算单位，不计入构表像素量；预算耗尽前已作出的排除判定仍计数。取消/失败保留已经完成的阶段及工作量，但与成功样本分开，不解释为一次完整匹配。

没有这些字段的旧记录仅展示总耗时，不补零。新字段作为完整一组验证，负数、缺项或超限记录计为无效，避免产生部分样本。阶段仅在边界计时，不逐像素计时；关闭识图观测不生成这些事件。各阶段百分位不能相加作为整次匹配百分位；微秒取整与残差采用饱和处理。

建议用户在相同设备、分辨率、模板、ROI、阈值下连续运行至少 100 次，再导出该次日志。之后可比较截图往返与匹配的 P50/P95/P99，定位大 ROI、多模板或慢后端。此批没有自动运行私人脚本，也没有宣称完成实际设备性能基准。

## 约束

2026-10-09：日志「识图统计」默认仍显示截图总耗时、采集/桥读取、传输/鉴权和帧入池四行。点「详情」展开常驻桥六个细分阶段：系统捕获、软件位图读回、读取像素、BGRA转换、桥写出/背压和桥接收。原始事件对应 `captureStagesUs.systemCapture/softwareReadback/pixelRead/pixelEncode/bridgeWrite/bridgeReceive`，单位微秒，页面转换成毫秒。系统捕获含显示器查询、参数构建和捕获调用；软件读回含 Bitmap 获取/转换及硬件资源释放；读取/转换/写出累计每块执行时间。桥写出包含最后flush和阻塞等待，不是纯复制耗时；桥接收包含像素及计时尾部读取，和桥读取/转换/写出并发重叠。绝不能将这些阶段或其百分位相加解释为采集总耗时。

细分数据只在认证能力协商成功且常驻桥确实提供时记录；兼容screencap和旧端不补零。每行用自己实际存在的样本独立计数，错误/不完整阶段数据不污染百分位。计时尾部及元数据均有固定长度和数值上限，失败不会拿部分帧继续运行。

按需批量写盘与停止解耦；引擎事件最多 256 条、写盘待写最多 256 条，单条 8 KiB，尾部终止元数据不进入普通事件队列。未完整结束的记录显示为「运行中 / 未完整结束」，不伪装成功。日志导出可能包含脚本主动输出的私人内容，分享前请自行检查。
