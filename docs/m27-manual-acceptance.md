# M27 手工 UI 验收清单（可执行版）

本文件把 [`项目交接与后续计划.md`](../项目交接与后续计划.md) 第 9 节的 16 项，展开成**可以照着做、能填结果**的步骤，并标明哪些已经被自动验收覆盖、哪些被运行时能力阻塞。

- 面向：执行验收的人（用户本人或接手的 AI）
- 基线：`wip/m27`，主机门禁 + 设备 smoke 均通过（2026-09-16）
- 设备：MuMu `127.0.0.1:16384`，Android 12 / API 32 / x86_64 / 720×1280 / density 320 / font_scale 1.0

## 0. 开始之前

```powershell
.\scripts\m27-gate.ps1          # 出 APK 到 build\m27-<时间戳>\
.\scripts\m27-ui-smoke.ps1      # 自动装包 + 跑 8 步路由回归，自动取最新产物
```

自动 smoke **必须先全绿**再做手工验收——它覆盖的是"页面能不能进、关键文字在不在"，手工清单只做它证明不了的部分。

准备一个名为 `VisualSmoke` 的可视化项目，至少含一个积木节点。

**如果出现所有点击都无效、界面像冻住**：那是 MuMu 卡死，不是 App 问题。完全重启模拟器（不是重启 App）。`Reset-App` 会识别这种状态并直接报错提示。

## 1. 状态说明

| 标记 | 含义 |
|---|---|
| ✅ 自动 | 已被 smoke 断言或截图比对覆盖，**不必重复人工做** |
| 🔶 部分 | 自动覆盖了一部分，剩下的列在"仍需人工"里 |
| ⬜ 人工 | 只能靠人做（手势、多步状态、禁用态语义） |
| ⛔ 阻塞 | 依赖尚未实现的运行时能力，现在做没有意义 |

## 2. 16 项逐条

### 1. 工作台 / 新建项目 / 项目卡展开的密度、字号、按钮顺序和颜色 — 🔶

已自动：项目卡展开态与 `08b_工作台_操作按钮展开.png` 逐值比对，72dp 行、12/10 padding、32dp 图标框、15sp+9sp、chevron 18dp、48dp 六按钮（启动 mint／编辑 accent／界面 purple／备份 mint／打包 secondary／删除 danger）全部一致。

仍需人工：**新建项目弹窗**（smoke 没点"新建项目"）。
- 操作：工作台 → 新建项目
- 判定：42dp 标题栏、三个分辨率选项（720x1280 带"推荐"、1080x1920、本机分辨率带"本机"）、点"?"切到"创建说明"且左侧出现返回箭头、底栏"取消 | 创建"

### 2. 点击编辑后先出现靠边小图标，而不是直接弹完整面板 — ✅ 自动
smoke 显式断言：出现小球后若检测到"函数"二字即判失败。

### 3. 小图标拖到屏幕远端，松手正确吸附且不回跳 — ⬜ 人工
- 操作：项目卡 → 编辑 → 按住小球拖到右下角 → 松手；再拖到左上角 → 松手
- 判定：跟手无延迟；松手后吸附到最近的左/右边缘并半隐藏；**不回跳到拖动前的位置**
- 背景：早先修过一个闭包捕获旧坐标的 bug，这条是它的回归验证

### 4. 面板标题栏能在全屏范围拖动，缩放手柄连续 — ⬜ 人工
- 操作：展开面板 → 拖标题栏到四个角 → 拖右下角缩放柄放大缩小
- 判定：能拖到屏幕边缘（面板可部分移出）；缩放连续不跳变；**面板最小能缩到比默认更矮**（默认 300dp，最小 260dp）

### 5. 标题"点击创建源文件"打开源文件管理 — ✅ 自动

### 6. 新建文件、文件夹，进入文件夹，长按多选，另存为、重命名、删除、分组 — ⬜ 人工
smoke 只打开了弹窗并断言底栏，**没做任何实际操作**。这是本清单信息量最大的一项。

- 新建：菜单 → 新建 → 输入中文名（如"测试流程"）→ 选"源文件"。判定：列表出现该名、`visual/flows/测试流程.jsonl` 真实落盘
- 新建分组：同上但选"分组"。判定：出现分组行，进入后为空
- 分组归属：长按选中文件 → 底栏"添加分组"。判定：文件移入分组，**磁盘路径不变**（分组是虚拟视图）
- 另存为：选中单个文件 → "另存为"。判定：副本有新名字，打开后结构与原件一致，但**两者的节点 ID 不重叠**
- 重命名：判定：改名后 `flow.call` 引用**不断**（回到调用方看节点仍正常）
- 删除：删入口 Flow 和被引用的 Flow。判定：**两者都被拒绝**并给出原因；未被引用的才删得掉
- 非法名：输入 `分组/文件`、`.hidden`、`名字 .jsonl`。判定：全部拒绝
- 重启 App 后复查：以上改动**全部还在**（这一条最关键，早先这里是内存态假实现）

### 7. 文件、工具、图像、判断、循环、常用、调试、函数、AI 九个入口逐个点击 — 🔶
已自动：文件弹窗、"更多"菜单。

仍需人工：其余七个逐个点开。
- 判定：都能打开、都能关闭、**不崩**；调试页七个开关应全部灰显并标"（未开放）"；AI 页明确显示未配置；图像页的 ONNX 标签页应标红说明属后续阶段

### 8. 插入命令后左侧程序树真实新增，位置选择正确 — ⬜ 人工
- 操作：选中一个节点 → 函数库选一条 → 弹出"选择插入位置" → 分别试"当前节点之后"和各子槽位
- 判定：程序树**真的**多出节点且在正确位置；保存后重进项目仍在
- 附带：Lua 项目里从图像/循环/常用页插入时，若片段含契约外的 API（如 `Runtime.getLoopCount`），应被拦下并提示"不在当前脚本 API 契约里"，**不能写进 main.lua**

### 9. 选中节点后删除、编辑、移动、缩进、撤销/恢复 — ⬜ 人工
- 判定：每个操作都改变程序树；撤销能逐步回退；恢复能重做；缩进到子槽位时弹"选择缩进分支"

### 10. 底部七个按钮的图标、点击行为和禁用态 — 🔶
已自动：断言了"编辑"按钮的 `enabled` 属性随选中态变化。

仍需人工：七个按钮（运行/单步/删除/编辑/数据回填/更多/控制台切换）逐个点，未选中节点时该灰的要灰。单步应提示"需要 Runtime 调试协议，当前版本未开放"且**不执行脚本**。

### 11. "更多"菜单的位置和五个条目 — 🔶
已自动：断言"录制动作"存在。仍需人工：确认五条目齐全、菜单位置贴着底栏按钮。

### 12. 第七按钮在程序树与日志间切换，日志不是假静态结果 — ⬜ 人工
本轮刚把控制台接到真实的 `RuntimeConsoleLog`，**尚未在设备上验证过**。

- 操作：点第七按钮切到控制台 → 观察空态 → 启动脚本 → 再看
- 判定：空态文案为"暂无运行日志／运行后引擎状态、Root 状态与失败诊断会显示在这里"；运行后出现**带时间戳**的真实状态行（如 `[10:23:45] 引擎 运行中`）；失败诊断显示为红色
- 注意：脚本内 `Log(...)` 的输出**目前不会出现**——那条链还没接到 Studio，空态文案已如实说明

### 13. 左上角最小化 / 插件 / 设置 / 关闭 — ⬜ 人工
- 判定：最小化收成小球；插件打开插件管理（八个单选项，"存储为模版"应禁用）；设置打开工具页；关闭退出悬浮编辑**回到项目列表而不是退出 App**

### 14. 所有中文正常，无乱码、裁切、重叠、异常字体 — 🔶
已自动：20 张截图全部人工看过；打包页"恢复默认／历史包名"的重叠已修复并二次截图确认。

仍需人工：本清单操作过程中随时留意。**已知易错模式**：给固定高度的 `Text` 用 `padding(vertical)` 会压缩内容框导致上下裁切，应该用 `wrapContentHeight()`。

### 15. 不出现 Material 默认淡紫，整体为紧凑白/蓝灰层级 — ✅ 自动
20 张截图确认；`AutoScriptPalette` 的 `app_*` 6 个与 `visual_editor_*` 14 个色值已逐个对过参考 `colors.xml`。

### 16. 返回键依次关闭菜单、弹窗、面板，不丢未保存内容 — 🔶
已自动：面板 → 小球 → 退出悬浮编辑回到工作台（曾经会直接退出 App，已修）。

仍需人工：**"不丢未保存内容"**。
- 操作：Lua 编辑器改几个字不保存 → 按返回
- 判定：弹出"放弃未保存修改？"，选"继续编辑"能回到编辑器且改动还在

## 4. 被运行时能力阻塞的项 — ⛔

以下现在做没有意义，等三个运行时问题修完再验：

- 单步运行（需要 Runtime 调试协议）
- 变量检查 / 变量信息（需要编译器变量分析、调试协议）
- 动作录制（没有事件录制流）
- 图像工具的取色/找图链路（属 M28）
- 脚本 `Log(...)` 输出进控制台（链路未接）
- **完整端到端**："创建项目→编辑→保存→Flow 编译→Root 截图/识别→输入→日志→备份→release→独立 Runner"。原先记为三个问题（`Timer.every` 回调完成路径、`StopPlan.release_pointer_ids` 被 JNI 丢弃、`InputArbiter` 未接真实输入），核实后是**同一个缺口的三个症状**：`AutomationBackend` 全仓库无实现，仲裁层从未接线。详见 [`input-runtime-gap.md`](input-runtime-gap.md)
