# ADR 0168：Root 空闲释放后按需重连

日期：2026-10-27

## 问题

原控制器将守护程序退出及认证通道断开统一作为启动故障，按 250/1000/3000ms 再次执行 `su`，连接成功又清零重试次数。整个会话空闲五分钟退出后，会重新申请 Root；虚拟系统未记住授权时可能反复弹窗。15 秒启动期限也可能在用户仍处理授权框时触发下一轮申请。

## 决定

保留服务初次初始化的一次 Root 启动，以兼容 Studio 及独立 Runner 的既有首次启动流程。随后空闲退出、连接断开、拒绝、启动超时及进程失败均只清理所属连接，不自动执行 `su` 或自动重跑脚本。再次运行/单步、截图、取点、录制或点击明确的连接入口才请求连接；刷新状态、读取输入能力及重组不触发申请。

授权等待最多 60 秒，认证连接仍使用原 7 秒期限；客户端按状态通知有界等待 70 秒，取消或会话更换后不执行原操作。不通过轮询、心跳、延长空闲期限或移除鉴权维持 Root。业务/优先停止连接仍共享原五分钟认证活动期限，断连继续清理触点及关闭输入安全栅栏。

控制器一次只保留一个启动请求；等待及已就绪时复用当前尝试。失败后只能由新的主动请求再试。准备、就绪、超时、进程结束及原生断连绑定本次尝试票据，旧回调不得结束或认证新连接。关闭先使尝试失效再分离原生通道，避免清理再次触发连接。

AIDL 协议升至 28，尾部追加 `requestRootConnection(expectedGeneration)`；仅接受同 UID、当前会话代次和可用的运行服务。返回接受不代表 Root 已认证，调用方继续等待真实 READY。未就绪且脚本运行/暂停/停止中时不得更换 Root 会话。旧协议客户端与服务明确拒绝混用，不改变项目 runtimeApi 或发布格式。

运行环境及权限页提供明确的连接 Root 入口，触控菜单打开/手动读取能力属于主动请求。截图前保持编辑界面可见，认证完成才沿原截图流程隐藏；悬浮截图仅保留一份当前项目/服务代次/悬浮入口修订绑定的等待，停用或换入口后不补做旧请求。

## 验证边界

定向主机检查覆盖空闲释放不重启、授权请求合并、拒绝/超时后主动重试、旧就绪/断连/超时隔离、取消/会话更换及固定诊断码。生产和测试 Kotlin 编译单独记录实际结果。

本批按用户要求不升 App 版本、不打包、不安装或发布，不连接设备或运行私人脚本；主机检查不冒充虚拟机 Root 授权框已复测。

实际收尾：Root 会话 5 项、诊断 4 项及客户端等待 9 项共 18 项主机检查通过；Runtime 服务/客户端和 Studio 的 Release 生产及测试 Kotlin 编译、共享 Runner 生产 Kotlin 编译通过，diff 空白检查通过。等待中的连接释放立即拒绝原操作，避免等待下一次连接；Runner 的运行入口允许沿同一启动流程请求 Root，不因空闲释放永久禁用按钮。保留首次 Wrapper/旧缓存失败及 PowerShell 参数错误记录，最终使用既有本机依赖缓存离线检查通过。
