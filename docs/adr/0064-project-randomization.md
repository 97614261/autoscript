# ADR 0064：项目随机策略与精确手势

状态：已实施。2026-10-11，用户确认实施；设备效果仍待验收。

## 决策

- 项目清单新增可选 `randomization`，包含普通触摸、识别命中动作和普通等待三项策略；默认关闭，备份及冻结 Runner 产物携带同一配置。
- 节点 envelope 新增可选 `randomization`（follow/disabled/custom），普通等待参数新增可选 `args.exactTiming`。参数、身份、源码往返和撤销仍以可视化数据为唯一真相。
- 只在明确的普通等待积木应用时间浮动。长按、拖动、录制生成的内部等待标记精确；持续触点期间也不随机等待。启动、轮询、超时、调度让步不受影响，零等待保持零。
- 位置偏移为实际屏幕 px 的独立 X/Y 整数范围；先使用宿主冻结坐标映射，再从合法偏移交集中抽取，不修改原始坐标或识图结果，不叠加普通触摸与识别策略。
- 同一任务的单指手势只抽取一次偏移；滑动已知两个端点时按整条线段边界取交集。分步手势遇到新点无法容纳既有偏移时明确失败，由既有任务清理释放触点，不夹边、不重新抽样。手势状态按协程隔离，弱引用，不进入日志或项目。
- 增加 API 1.8 的只读 `Input.resolvePoint` 及屏幕像素移动/滑动。映射仍由 Rust coordinate 实现，UI 不复制映射算法，不增加 Root 指令或后端。
- 像素输入增加可选 `snapshotId`（1.8），随机化总是传递解析时的身份；宿主准备输入时复核，拒绝解析之后已经变更的映射。省略时保持既有像素 API 语义，不虚构设备提交与物理屏幕变化的原子性。
- 不实现每行随机停顿、随机轨迹或 App 级策略；不修改既有精确 Input/Task API 的默认语义。没有开启策略的旧项目不产生额外宿主调用。

## 验证

模型/Schema 同边界校验，旧清单默认关闭；源码元数据无损往返；执行测试覆盖零等待、手势内部精确、边缘取样、单手势偏移、识图结果不变、任务隔离及快照防护。取消/触点清理继续复用既有实现和全工作区回归，不冒充设备实测。结果见[验证记录](../verification/project-randomization-2026-10-11.md)。
