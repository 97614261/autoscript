# ADR 0043：智构本地工作台与真实入口

后续决策：用户已明确要求跨App编辑，原宿主边界由[ADR 0044](0044-cross-app-visual-editor-host.md)扩展；下文保留本批当时范围，不再代表当前编辑入口。

2026-10-04，接受。用户要求重新设计首页、“我的”和入口。

## 决策

- 首页替换推广轮播，默认进入紧凑本地工作台：新建、导入、最近项目、权限、运行环境、备份和函数文档。
- 底部导航为“首页 / 项目 / 我的”。项目管理保持现有Store和正式可视化编辑链路，跨页快捷操作由一次性内存请求交付，不保存为工程数据，不直接从首页运行私人脚本。
- “我的”不以未开放账号登录作为前置条件，不显示可点击却无功能的社区/市场入口；只呈现本地真实入口及运行边界。
- 函数文档复用生成契约驱动的函数库，只读浏览，不生成积木，不假装已授权项目能力。
- Runner连接、Root就绪、运行状态分开显示；不因此宣称输入和截图已实测成功。
- 首页改动不删除或改写项目、历史源码工程、备份、协议与应用私有目录。

## 跨App编辑的核对

现有EditorDock与最小化球是MainActivity内Compose内容；系统WindowManager悬浮由runtime-service用于运行控制、截图、选点与录制。悬浮权限本身不能让Activity编辑内容跨App显示。

真正跨App编辑需要Studio拥有独立悬浮宿主、生命周期/Compose焦点与子弹窗支持、后台存活/退出清理以及与运行窗口的互斥。此为另一个实施范围，不能通过把Activity内小窗称为“系统悬浮”冒充完成。等待用户明确选择是否本批一起实施；未确认前本ADR不授权新建该宿主。
