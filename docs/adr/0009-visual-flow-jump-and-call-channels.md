# ADR 0009：可视化 Flow 的跳转和调用参数

## 背景

“跳转”面板目前输出 Lua 文本。除等待外，积木编辑器没有对应节点；
`Runtime.setParameter` 等文本也不是已注册的脚本 API。插入后显示一行并不等于可运行。

## 决定

- 跳出循环、标记、跳转标记、返回上层与调用/返回参数都应成为有版本的 Flow 节点；
  Studio 校验并编译，Runner 仍只加载冻结 Lua。
- 标记只允许在同一个 Flow 的根层级跳转，不跨 Flow、循环或分支；编译时检查目标存在、
  名称唯一，避免 Lua `goto` 跳入局部变量作用域或绕开循环边界。
- 跳出循环仅允许在循环体内。返回上层结束当前 Flow 调用。
- 序号调用参数走下一次 `flow.call` 的独立通道；目标 Flow 可按序号读取，已声明的
  命名参数同时得到该值。一次调用后清空待发送参数，返回值保留给“获取返回参数”。
  返回参数也是 1～99 的序号通道；项目声明的返回类型只约束第 1 个值，
  其余序号按运行时标量传递。
  不把未注册的 `Runtime.*Parameter` 文本当作执行能力。
- 现有 `flow.call` 与 `task.sleep` 保持兼容；新增能力逐项落地时须同时更新节点 schema、
  catalog、编译验证、代码生成和测试，不允许仅把入口改成新的文字标签。

## 后果

旧 Lua 编辑仍可使用 Lua 原生 `break`、`goto`、`return`，但可视化入口必须按节点契约工作。
尚未落地的跳转动作不得静默映射为无关积木或默认值。
