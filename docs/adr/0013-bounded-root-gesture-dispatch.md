# ADR 0013：可取消滑动的分段输入

状态：实现完成，主机与两ABI构建验证通过；实际设备待验收。日期：2026-09-29。

为 API 24/25 增加 APK 内随 runtime-service 分发的 Kotlin RootInputBridge，由 RootDaemon 以固定 app_process 主类启动。桥只读取三个整数的白名单指针事件，不提供 Context、Binder、反射对象或 shell 给 Lua。反射 InputManager/新版 InputManagerGlobal 仅存在于特权宿主适配层。启动握手成功才宣布单指能力；无桥的旧启动参数继续兼容原行为。原始帧协议和认证 socket 不变。常驻桥降低每个 MOVE 启动系统 input 进程的开销，但不声称已测性能。

桥进程读写设置有界超时，EOF/退出尝试释放触点；清理失败向上报告并拒绝继续业务。Installed APK 路径仅由服务启动配置提供，不能由脚本或请求指定。

系统 input/screencap 子进程也设置硬截止时间。子进程退出等待使用 waitid(WNOWAIT) 保留未回收的 PID，先停止并加入 watchdog，再调用 Child.wait 回收，避免 watchdog 对重用 PID 发信号。超时输入不自动重试（可能已部分注入），仅确定的普通失败延用旧重试策略；旧原生 swipe 的期限保留用户时长加余量，不能用超时冒充即时停止。

仅在认证握手确认单指 down/move/up 能力时，把滑动转换为一个受仲裁的连续事务。最多 200 个位置段，坐标用 i64 插值并精确到达终点；总时长保持用户设置。每个事件均检查优先停止/取消，等待间隔使用宿主控制通知和截止时间，不轮询 Lua VM。

不改变设计坐标映射，不绕开指针所有者、租约与清理。桥初始化成功时API24/25也使用连续单指路径；桥与系统单指命令都不可用时保留原生swipe。当前Daemon独立通道可以终止该系统input子进程，再尝试UP；不支持/失败的释放明确报错并禁止继续输入，不提前声称正常停止。旧Daemon未协商优先位时仍只具旧能力。禁止多次抬起/按下冒充连续滑动，也不自动禁用长滑动。

后续单命令抢占必须保留认证、序列和响应关联，并确认杀死注入进程后系统触点可清理；不能提前报告脚本停止而后台继续注入。

## 用户确认的后续方向（2026-09-29）

用户确认借鉴新版易编的独立停止通道与异步释放触点思路，目标是可验证的可靠性改进，而不是仅复刻 upall 命令。参考 InputRuntimeManager.releasePointersForStopAsync 与 x.bd.a 可确认专用 __stop_release__ 通道发送 upall；不能据此证明参考 native 滑动内部已停止后续 MOVE，更不能宣称本项目已比参考实现性能更好。

- 优先停止路径独立于普通输入请求排队，但必须绑定现有随机会话身份、所有者、事务/代际和重放保护；不开放新的任意 shell 或任意 PID 操作。
- 先使旧事务失效并阻止后续注入，再终止必要的进行中操作、释放该事务的触点。不能只发 UP 后让旧滑动继续发送 MOVE。
- 正常停止须确认注入已终止且触点清理成功；等待有截止。超时、桥断开或释放失败必须明确报错并拒绝继续输入，不能冒充正常停止。
- 不重复执行可能已部分注入的操作；旧会话/迟到响应不得影响新运行，停止后重新运行须从干净状态开始。
- 保留连续滑动及用户已有行为，不自动禁用长滑动；不引入免 Root 后端。具体优先控制协议在实施前补充定义与兼容策略。
- 验收覆盖长滑动中停止、按住中停止、并发/重复停止、迟到请求、桥崩溃、释放失败与重新运行；主机故障测试和真机停止时延、触点残留分别记录，不以单元测试宣称设备性能优于参考。

## 优先控制协议（已实现）

增加业务 socket 的 `.ctl` 同目录端点，权限/peer UID 校验相同；密钥通过 HMAC-SHA256 和固定域标签从会话密钥派生，独立序列认证，业务报文不能跨通道重放。协议版本3不变，增加 INPUT_PRIORITY_STOP 协商位；控制端点握手后只允许 Cancel。Cancel 的8字节值为业务输入请求ID截止水位，不是 Lua 任务ID或PID。

客户端发送输入与停止共用短临界区；停止封闭新输入并取得最后发送ID，经独立线程发控制请求。服务端先提高水位、取消旧请求，再等待注入退出并发送UP；迟到旧ID不得注入，旧停止不得释放更高ID的新触点。watchdog只终止当前请求持有、未回收的 input 子进程；取消/超时不重试。控制应答仅在释放成功时为OK，失败锁住后续输入，必须重建会话。恢复输入必须已收到清理成功应答。主机测试验证水位/认证/并发逻辑，设备触点清理效果仍需用户验证。

独立控制读取应答期限8秒、写期限2秒；当前桥单次2秒、采集5秒，因此停止仍可能等待一个有界宿主操作。过期成功应答不能解除失败锁，重复停止合并；旧水位低于已开始的新输入直接应答，不等新长滑动的锁。控制完成通知唤醒服务；正常Stopped要等Root本地清理结束，失败立即有ROOT_STOP_CLEANUP_FAILED诊断。业务EOF有独立清理守卫，不依赖仍持有Arc的控制线程退出后才清理。主机测试不证明厂商内核/反射接口已释放真实触点。
