# ADR0143：ARM 认证加速与截图共享存储

日期：2026-10-23。状态：已实施；本轮主机门禁与最终候选两端性能/编辑回归完成，有限设备边界见[执行报告](../verification/capture-hotpath-2026-10-23.md)。

## 决定

用户要求继续修复可完善的问题及优化性能。本批针对已定位的开销，不改变识别算法、默认 full/V4、Root 协议3、60KiB分包、HMAC-SHA256、重放检查、完整帧期限或优先停止。

- 仅 AArch64 启用现有 sha2 0.10.9 的 asm 后端；由上游 cpufeatures 在运行时检测 SHA2，缺少指令仍用其软件实现，不为整个二进制强制 target-feature。不自行实现 unsafe 加密代码。新增传递依赖需核对许可证、Android API24兼容及产物体积。
- 普通截图与短缓存复用 automation-core 已有 SharedPixels，移动接收 Vec 后只克隆不可变所有权，不再 Vec 转 Arc 切片复制整帧。缓存及帧池均按实际 allocation_bytes 计费；容量、租约、几何、代次、取消和新鲜度校验保持不变。
- 流式接收预留有界最终容量，仅在每个包通过认证、顺序、身份及长度检查后追加数据，不预先清零完整帧。失败丢弃未完成帧，不能发布部分像素。
- SecureChannel 调试输出不显示会话密钥；此修复不声称已有密钥泄露。测试和报告不记录项目、画面、用户变量或密钥。
- 全屏候选的行区间及锚点孔位整理延后到锚点比较通过之后；尽早淘汰的候选不做无用排序，不改锚点顺序、像素比较顺序、预算/取消检查点或得分。

## 验证

保留当前0.1.3候选及同一QA作为新基线；以真实点击使缓存失效，记录设备、ROI、模板、分位数及完整流程，不把CPU微基准当截图性能。验证HMAC标准向量/篡改/重放、软件回退编译、共享地址及容量预算、失败帧拒绝、重复生命周期及取消清理。两ABI构建及实际设备结果分开，PSS变化不直接等同泄漏或无泄漏。线上仍由用户发布。
