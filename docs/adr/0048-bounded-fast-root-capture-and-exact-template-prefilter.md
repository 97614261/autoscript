# ADR 0048：有界 Root 快速截图与等价模板预筛

状态：接受（2026-10-05，用户要求优化截图及识图性能）。

## 决定

保持 Root-only、原像素、原阈值和确定性搜索方向。协议 v3 新增可协商 CAPTURE_STREAM 能力和 CaptureStream 命令；一次请求返回元数据和连续有界认证数据包。每包仍有 HMAC、序列号、请求关联和偏移校验，最多 64 MiB。旧端未协商此能力继续使用 Capture/CaptureChunk；不扩大全局包上限、不移除鉴权，不经文件或 AIDL ByteArray 中转。

RootDaemon 优先使用独立常驻 app_process 截图桥，通过系统 SurfaceControl/ScreenCapture 获取当前画面，和输入桥分离。仅固定截图命令，隐藏 API 不可用时本会话降级到既有有界 screencap，并在观测中标注真实后端。禁止捕获安全图层、偷偷缩放或用旧帧冒充当前帧。子进程、数据量、等待及停止均有界；退出回收管道、位图和进程。首次兼容失败不得导致每轮重复启动失败桥。

后续收口（2026-10-06）：桥使用最多32行且最多64 KiB像素的批量读取工作区，跨同尺寸帧复用，不缓存截图本身；仍经 getPixels 获取既有未预乘 ARGB 语义并显式转换 BGRA，不改用未经验证的原生字节序拷贝。认证协议提供借用解码载荷及有界接收缓冲复用：完整验签、序号、状态和形状校验后才暴露切片，切片寿命不得超过包缓冲；传输读取错误清除有效长度，鉴权/关联/半帧错误保持关闭连接，不扩大全局上限，线格式与旧拥有式接口不变。

截图观测增加采集（包含读取桥输出）、传输/验证、入帧池时间及真实后端/传输方式；总体宿主往返仍独立，不把分段相加伪造整轮百分位。开发构建对截图协议、哈希及视觉热路径启用优化，仍保留 Debug 签名和溢出检查。

Rust 模板匹配增加常见颜色积分预筛：一个候选窗口若连模板主色所需最低像素数都不满足，则在数学上不可能达到原阈值。只做必要条件排除，幸存候选仍按原逐像素算法精确评分。透明策略、容差、搜索顺序、步长、结果分数与数量保持不变。积分表最多 8 MiB，创建与遍历共享比较预算和取消/截止；小区域或不适合的模板使用原路径。

## 验证与限制

2026-10-09 后续决定：零容差模板可增加一个辅助 RGB 粗分桶必要条件（透明/非透明分桶分离），并用已有主色积分表校验最多四个模板象限。每个区域使用整模板允许不匹配数作为保守上限，不能把区域比例当成独立相似度。辅助桶至少拥有超过允许不匹配数的有效像素才启用；至多两张积分表合计仍限 8 MiB，预算不足或条件不适合时沿用既有路径。粗分桶只用于排除不可能候选，幸存者按原精确颜色评分，非零容差不使用这些新增条件。四个原锚点及其比较顺序不变，不增加未经证明的抽样判定；收益用合成找到/未找到及完整等价回归验证，不套用用户设备收益。

首候选按原精确比较检查，若已经满足首结果或多结果上限，跳过积分表构建；否则从第二候选开始构建并预筛，首候选不重复比较。仍按相同方向/模板优先级返回相同分数，已实际执行工作消耗同一资源预算；不要求优化前后的预算消耗数相同。新增固定模板特征结构计入估计资源费用。

2026-10-09 精确比较后续：零容差、无需要跳过的透明像素时，可按32像素行段批量计数。只有剩余允许不匹配数、剩余比较预算和距离下一取消检查点均足以覆盖整块时才批量执行，因此块内不可能提前失败，也不跨过原检查点；边界、透明跳过、非零容差仍逐像素执行。模板内部以4字节BGRA数组取代4字节Color存储，准备时按规范RGBA计算内容哈希、锚点及预筛特征，随后只存一个BGRA像素向量；不增加长期模板副本，不改变资源估计尺寸。让Root BGRA帧精确比较无需每像素交换模板通道；RGBA帧、非零容差及测试参考按真实字节序转换。保持原实际比较数、预算剩余、失败位置、分数及取消检查次数，不使用 unsafe、额外帧副本或近似评分。

找图侧补充（2026-10-09）：观测按调用记录准备/收尾残差、预筛构建、遍历与精确比较合计时间，以及候选/预筛排除/实际比较量。只在阶段边界计时，关闭观测不构造日志；不记录模板身份或像素。零容差比较按格式和透明策略在候选外层选专用行段路径；已比较锚点作为至多四个行段空洞，不在每个像素检测锚点成员。

对零容差、已有主色积分表的模板，可加互补必要条件：若相关模板像素数为N、主色数为F、最多允许A个不匹配，窗口必须至少有max(N-F-A,0)个非主色像素。因而窗口主色数不得超过完整模板面积减该下限；忽略透明时仍用完整面积，避免误排。非零容差不应用此上限（颜色允许区间可能重叠）。复用原积分表，无额外画面缓存或积分表。保持评分、候选/模板顺序、步长、透明语义、总资源限额及取消截止不变；原比较器仅作为测试基线。

2026-10-09 失败诊断：可选 `CAPTURE_FAILURE_DETAILS` 协商位仅允许采集失败携带4字节白名单原因，旧端错误载荷仍为空。原因区分采集截止、回退进程启动/读取/退出、帧格式及ID耗尽；客户端额外区分传输、鉴权/协议、请求关联及取消。JNI仅输出固定错误码，不透传任意异常文本或私有路径；流式失败仍作废连接。停止标志优先于回退错误，不把停止伪装成后端失败。100次独立生产链路截图成功仅证明该条件没有复现，不宣称已修复缺少具体原因的用户故障。

2026-10-09：Root发送侧增加默认兼容的分块填充接口及可复用认证包编码，生产路径直接从已捕获帧切片复制到发送载荷，取消检查仍在独立优先停止栅栏下执行。每个包完整编码/验签后才推进，失败清除有效长度；不改变线格式、分块大小、帧上限或超时。新增CAPTURE_STAGE_TIMINGS协商位，流式元数据可携带六个有界微秒阶段：系统捕获、软件位图读回、getPixels、BGRA转换、桥写出（含flush/背压）、接收像素及阶段尾部（与桥写出重叠）。旧端仍获得49字节元数据；没有细分数据的回退不冒充零耗时。桥命令1保持旧格式，命令2新增固定计时尾部；尾部异常按半帧处理。计时只记录结构化数字，不记录像素、模板路径或私人源码，不相加阶段百分位。

使用合成帧验证鉴权/重放/偏移/截断/旧端兼容、桥边界和像素字节序、等价评分及五方向/透明/容差/多结果/取消。不运行用户私人脚本。构建和模拟器安装按既有门禁；性能提升须用户以同设备、ROI、模板和至少 100 次样本验证，不承诺未经测量的加速倍数。厂商隐藏 API 不受公开 SDK 稳定性保证，降级应可见且不冒充快速采集。
