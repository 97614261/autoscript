# ADR 0051：精简运行事件与有界长时间日志

状态：接受（2026-10-09，用户要求继续优化并精简单条日志）。

## 决定

引擎与JNI的既有安全观测协议不变，在私有文件写盘线程将版本1识图事件转换为版本2紧凑文件记录。相同条件单独存一次，样本只写条件引用、结果、耗时、接收时刻与固定顺序的数值数组。完整保留原条件、阶段和工作量，不写源码、变量或图片内容。条件表有容量与数量上限，不能编码的事件保留原格式，不静默删除字段。读取端同时支持旧完整事件与紧凑事件；缺条件或损坏记录明确计为无效。

事件明细使用有界分段，最多8段、每段256KiB；条件表最多256项且256KiB。到限额淘汰最旧明细，最新错误/停止仍可记录，淘汰数量明确显示。累计操作次数在写盘线程处理入队观测时更新元数据，不由当前保留明细反推；普通队列丢失仍计数、仍标观测不完整。P50/P95/P99仅覆盖保留明细且使用同条件/结果分组，不将窗口百分位冒充整次运行百分位。旧单文件可读且不自动迁移或删除。脚本和运行诊断独立通道及既有上限不变。

写盘、读取和导出均有界；停止不等待文件IO或统计汇总。分段和条件关联由共享文件层处理，Studio与独立Runner使用同一实现。读取不执行用户数据，不允许路径跳转或链接越界；轮转仅删除本会话确切命名的事件段，旧运行清理保留未知文件。

运行服务在独立进程，进程内锁不能保证快照一致；读/写/导出通过每运行的文件锁协作，获取期限1秒，仅日志IO使用。条件表、事件段和快照元数据在同一读锁下取得，写盘与轮转在写锁内完成。锁超时明确失败，不读半条日志，不阻塞脚本停止。

认证优化保持逐包HMAC-SHA256、时序、关联和常量时间比对。先核对哈希后端与预置状态的可测收益，只有等价且有收益的变更才交付；不改变线格式、降低安全或强制不兼容CPU指令。

## 验证

紧凑往返与旧格式混合、缺失/冲突条件、字段损坏、条件容量回退、分段轮转/读取/导出/路径边界、累计次数与明细窗口分离、背压和停止尾部、旧数据与独立Runner构建。压缩大小与认证对照只用合成数据，记录设备与口径，实际私人脚本由用户统一验收。

实施及验证结果见 [交付记录](../../archive/project-history/2026-10-10/docs/compact-run-log-delivery.md)。合成同条件1000条完整截图记录635000字节，紧凑存储139291字节；认证预置复测中位收益近零，未引入生产鉴权变更。
