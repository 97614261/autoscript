# ADR 0123：新生成实体使用紧凑 ID

## 状态

已接受（2026-10-17）

## 决策

新建项目使用带语义前缀的 96 位随机 URL-safe token，例如 `project-<16字符>`；可视化积木在整个项目范围内按最大历史后缀递增，例如
`node-1`、`block-2`，页面和控件使用 `page_1`、`copy_1` 形式，新插件使用 `flow-1` 形式。已有 UUID 形态的项目数据、插件数据和积木数据保持不变，
不做批量迁移、不改变引用、不修改导出文件的历史身份。

运行日志会话 ID、系统选择令牌、SHA-256 内容/组件 ID、发布摘要和跨进程协议字段继续使用既有固定格式。
它们是清理、鉴权、完整性或协议兼容边界，不能仅为显示长度而改变。

## 影响

- 新文件夹、JSONL 和 UI 草稿更短，日志和调试界面保留完整真实身份。
- 读取器继续接受原有 UUID 和新的短 ID，旧项目不受影响。
- 项目 ID 的 96 位随机空间足以覆盖当前项目预算；节点数字后缀只用于区分，不承担密码学密钥职责。

## 2026年10月19日真机回归修正

编译器既有约束要求项目内的节点身份及积木区身份全局唯一，单插件递增会造成新建插件和组合草稿冲突。
保留该编译约束，不迁移旧身份。编辑会话共享项目级数字高水位，初始化纳入全部正式插件，新建、复制、
源码解析及恢复草稿继续预留身份；撤销、删除或取消预览不降低会话高水位。节点与积木区分别使用 `node-N`
和 `block-N`，不把随机项目身份、运行代次或鉴权令牌改成数字。校验及陈旧草稿复核仍为最终提交边界。

## 2026年10月25日图像加入补修

图像/OCR加入会在独立候选编辑器中准备整批积木，再经过全项目编译及原上下文复核提交。
叶节点批次和含子区的积木森林必须继承原编辑器的同一个项目身份分配器，不能因候选不立即提交而退回
单插件编号。候选仍不改变当前草稿、选择或撤销历史；校验拒绝、取消及撤销不回收已分配编号，允许编号
有空缺。保留编译器对跨插件节点与积木区身份的全局唯一校验，不重编号或删除已有用户数据。
