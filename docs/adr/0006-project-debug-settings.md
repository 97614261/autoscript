# ADR 0006: 项目调试设置冻结到启动计划

## 决定

调试设置属于项目，不属于 Studio 设备偏好。项目清单保存一个严格、版本内兼容的
`debugSettings` 对象；启动前由 Studio 将其应用到冻结后的运行计划。

已实现 `runDelayMs`：Studio 用一个闭包包装冻结 Lua 入口，使其在任务调度器内
执行 `Task.sleep` 后再调用原入口。这样延迟可取消、不会阻塞 Binder 或 UI 线程，也不需要
把延迟实现泄露给 RootDaemon。

增加 `showRunPrompts`（默认 `true`）控制脚本面向使用者的运行提示是否显示。关闭时，Studio
在启动计划中屏蔽 `Prompt.show`；脚本调试日志 `Log.*` 与 Runner 状态/错误诊断不受影响。
旧项目缺少该字段时迁移为 `true`，保持既有提示行为。

`runPromptFilters` 保存可视化 Flow 的自动提示类别：循环、判断、Flow 进入/返回、寻图、变量。
变量类别还可按作用范围、类型和名称筛选。编译器在对应节点生成轻量事件钩子，Studio 在
冻结运行计划时按项目设置绑定钩子；未勾选的类别不产生用户提示。手动加入的“弹出提示”
节点与自动类别无关，仍受 `showRunPrompts` 总开关控制。旧项目缺少筛选对象时补入全关闭的
默认值，避免升级后出现大量自动提示。手动加入的“弹出提示”由 ADR 0008 的短时
`Prompt.toast` 通道显示，样式由同一项目的 `popupStyle` 保存。

运行提示窗由 Runner 管理：可拖动，点击可选择关闭或后台隐藏。后台隐藏时继续接收最新
提示，通过运行浮球重新打开；脚本结束后保留提示与通知，直到用户关闭提示窗。脚本日志
仍只进入开发者日志通道。注释节点仅参与编辑和生成，不产生运行时副作用。

## 后果

- Lua 和可视化 Flow 获得相同、项目级的运行延迟语义。
- 运行提示显示设置按项目保存；隐藏提示不会静默脚本调试日志或 Runner 诊断。
- 生成物的完整性仍在包装前校验；运行时拿到的仍是单个冻结 Lua 模块。
- 其它参考应用调试项只有在 Runtime 有对应强类型能力时才可启用。首发 Root 范围不提供
  系统录屏、无障碍按键或无障碍音量停止。
