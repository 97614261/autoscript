# ADR 0008：短时弹出提示与运行提示窗分离

## 背景

先前手动加入的“弹出提示”与可视化 Flow 自动运行事件都走 `Prompt.show`，Runner
把它们显示在同一个常驻浮窗。手动提示不会按时间消失，也不能按项目配置尺寸、字体和背景。

## 决定

- `Prompt.show` 保留给自动运行事件的可拖动、可后台隐藏提示窗。
- 新增 `Prompt.toast`（opcode 1102，Runtime API 1.6）。可视化 `task.prompt` 和编辑器
  “弹出提示”使用该接口，Runner 以独立浮窗显示，到期或点击后关闭。
- 项目 `debugSettings.popupStyle` 冻结尺寸、左上角 X/Y 位置、背景/字体 ARGB 色、字号、圆角、
  持续时间和文字对齐；新项目默认显示 3 秒、黑色半透明背景、白色 32px 字体。
- 可编辑的几何和文字尺寸统一用物理像素 `px`；`xPx` / `yPx` 为 `-1` 时自动居中。
  旧版 dp/sp/百分比配置在 Android 项目存储层按当前设备密度与屏幕尺寸转换，
  避免用户已保存的提示窗突然缩小或位移。持续时间仍用毫秒。
- Rust 对样式 JSON 做严格字段与范围校验。JNI 沿用有界提示事件队列，事件序列化为
  `window` / `toast` 两种带类型消息，Runner 只按已验证的类型显示。
- 短脚本结束后，Runner 前台生命周期最多延续到短时提示到期，避免提示刚弹出就被销毁；
  超时、点击关闭或悬浮窗创建失败都会释放该保持状态。

## 后果

脚本调试日志仍与两类用户提示隔离。项目设置通过启动计划绑定，不增加 Runner 对
Studio 项目列表或编辑器的依赖。无悬浮窗权限时使用系统 Toast 回退，定制样式不可用。
