# ADR-0007：一键玩式单指按键编辑流程

- 状态：已采纳（实现分阶段交付）
- 日期：2026-09-22
- 影响模块：Studio 输入编辑、Runtime Overlay、Flow 编译、Lua API、Root 输入仲裁

> 2026-09-29 补齐：系统悬浮选点、七种动作快捷入口、共享插入位置、整批撤销及保存失败反馈已接线。
> 仅为代码/主机检查交付，尚未进行设备验收；本 ADR 不代表全部验收通过。
> 当前链路与设备边界见[按键流程交付](../input-ui-workflow-audit.md)。

## 背景

Studio 悬浮编辑器当前的“按键”入口打开的是输入函数库，只有 `Input.tap`、`Input.swipe`、
`Input.keyEvent` 快捷项，不具备一键玩式的浮动手指选点和操作插入流程。一键玩的旧版实现先
显示可拖动的手指浮标，用户拖到位置后点浮标选择单击、按下、弹起或拖动；拖动还会增加一个
终点浮标，最后选择插入到当前插件的位置。

当前 Root 输入后端已经有结构化单指 Down/Move/Up 命令和停止释放基础，但客户端、RootDaemon
只声明 `INPUT_POINTER_SINGLE` 并接受 ID=0。输入仲裁器还要求每笔事务内部配平 Down/Up，不能
直接暴露跨 Flow 节点的按下/弹起。

## 决定

1. “按键”采用一键玩式工作流：进入后启动 Runner 的短期系统悬浮选点会话；显示一个可拖动的
   手指浮标。拖动只移动浮标，不注入目标触摸。点浮标打开动作选择面板。执行目标触摸只发生在
   用户明确确认“加入”并运行脚本时。
2. 动作选择包含单击、按下、弹起、长按和拖动。单击/按下/长按需要起点；拖动需要起点、终点
   和时长；弹起只释放当前 Flow 持有的单指。另提供“截图选点”，复用 Root 截图交接及图像画布
   的坐标映射，作为浮标定位的替代方式。
3. 所有动作都通过 Studio 现有插入位置流程写入当前 Flow；Lua 与可视化编辑共享选点状态和坐标
   转换，分别生成受契约校验的 Lua 调用或结构化积木。Runner 只持有不透明 project/flow 标识，
   不依赖 Studio 实现。
4. 第一期只支持 Root 已具备的手指 ID=0。UI 不呈现会被后端拒绝的 ID=1–4；多手指不属于本 ADR
   的交付范围。
5. `pointerDown` 建立带 Task 身份和超时的输入租约；只有持有该租约的任务可以移动或释放手指。
   正常弹起、任务取消、任务失败、运行停止、会话重建和租约超时都必须释放触点。按下节点不能
   通过一笔不完整输入事务绕过仲裁器。
6. 长按作为有界复合动作执行：按下 → 定时等待 → 弹起。等待使用 Runtime 定时能力，不用 UI
   计时器或固定周期轮询；取消/停止也必须触发释放。
7. 弹窗沿用 Studio 当前白底、蓝色强调、浅灰描边、紧凑分组卡片和底部操作栏。动作面板使用
   易点按的动作卡片；定位/设置子面板显示当前动作、坐标和时长，并提供取消与加入。悬浮浮标
   延续 Runner 现有蓝色浮窗体系，并提供明显的起点/终点区分、关闭/取消入口。
8. 浮标坐标先转换为物理显示坐标，再由统一坐标映射转换为项目设计坐标。旋转、安全区、项目
   分辨率和 scaleMode 均进入转换；不在 Studio 与 Runner 各实现一套公式。

## 交互状态

| 状态 | 屏幕表现 | 用户动作 | 结果 |
|---|---|---|---|
| 等待定位 | 一个手指浮标；底部轻提示“拖到目标位置，点手指选择动作” | 拖动浮标或点浮标 | 记录起点，打开动作面板 |
| 选择拖动终点 | 起点固定，出现“终”浮标 | 拖动终点并点浮标 | 记录终点，打开时长设置 |
| 动作确认 | 样式统一的轻量参数面板 | 调整时长，点“加入” | 回 Studio 插入位置选择并写入当前 Flow |
| 已插入 | 收起本次选点浮窗 | 继续编辑或运行 | 新节点/代码显示在目标 Flow |
| 取消/失败 | 显示简短原因，浮标移除 | 重新发起 | 不产生半成品节点，并释放所有触点租约 |

## 验收条件

- 点位浮标可在其他应用上移动；移动浮标本身不会触发目标应用输入。
- 单击、按下后跨节点移动再弹起、长按和拖动生成正确坐标及节点顺序。
- 用户选定 Flow 和插入位置后，节点真实持久化；关闭重开仍存在。
- 按下后停止/取消/异常退出不留下触点；无效顺序由编译器或仲裁器拒绝。
- 竖屏、横屏、安全区、不同设计分辨率和缩放模式的点位结果与截图画布一致。
- 设备无悬浮窗权限或 Root 指针能力时，入口明确报出不可用原因，不显示假操作。

## 后果

### 2026-09-29 补齐实现约束

- Runtime AIDL 升至 v19，选点通过独立一次性回调返回强类型物理坐标、屏幕尺寸、动作和时长；不传 Lua 或项目文件。单会话、120 秒截止、Binder 死亡/旋转/Root 断开/停止取消，迟到回调由请求 ID 和会话代次拒绝。
- 浮标为 `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL` 的小窗，使用实际 `getLocationOnScreen` 中心作为物理点；起点和终点各自独立，不能以面板或窗口的局部坐标生成脚本。
- Studio 与截图工具共用 `ImageToolCodeGen.DesignMapping` 和强类型输入积木生成。所有输入动作进入同一个插入位置弹窗；复合动作在一次撤销事务内插入上方/下方/子块/底部。
- 加入后关闭定位工具；保存失败保留脏草稿并明确提示“未保存”，重试只保存，不重复加入。进程死亡不恢复未确认选点。

- Studio/Runner 交接只传有格式校验的一次性会话数据；不传 Lua、Root 命令、文件描述符或可执行负载。
- Flow/API 契约、Lua stub、编译器、Runner 输入会话和 Studio 悬浮选点需要分阶段实现及测试。
- 当前单指限制保持明确；要支持 0–4 并发触点，必须另行设计真实多点注入后端及能力协商，不能仅扩展 UI 下拉选项。
