# ADR0111：识别等待判定与任务所属结果缓存

2026-10-14。用户授权执行识图收口1–6，先代码、编译与静态检查，测试执行及安装后置。

2026-10-15更新：下述“指定文字要求完整识别”仅继续用于完全一致；新建包含目标等待改用同帧逐字结果定位，规则由[ADR0112](0112-studio-coverage-and-recognition-workflows.md)取代，其他缓存和安全边界不变。旧已保存组合不自动迁移。

- 字库等待不修改普通OCR文字或分数输出。非空条件至少有一个已通过字库阈值的字符；指定文字条件要求本次完整识别，避免未识别占位符`?`被当作目标文字。覆盖率及条件状态使用不同的声明整数变量；工作变量、原有识别输出及条件变量禁止冲突，选择器与提交校验共同执行。
- 等待仍为可见普通积木。完成状态1表示条件完成，0表示总期限或次数耗尽；耗时为单调实际经过时间。超时在识别前后判断，不能中断不可取消的第三方调用；异常与停止直接终止，不伪装正常未命中。
- Screen.recognitionValue保持原API及5122操作码。执行器最多缓存一份64KiB来源JSON和已校验结果，精确绑定TaskToken、来源字节和类型；任务变化/来源变化替换，所属任务取消或结束清理。不保存到项目、不写日志、不缓存屏幕或识别结果来冒充新识别；缓存命中仍逐次检查字段和序号。IMAGES复用原版本1形状校验。
- 字库预览支持图框/列表联动，以及配置所选序号的结果读取；预览序号不是下一帧字符身份，不冻结为点击坐标。读取配置必须另选真实运行期逐字结果字符变量和匹配类型接收变量，通过既有整批校验、位置选择和一次撤销加入，不隐式截图、建变量或执行。
- 不扩模型、不实现下载器或独立Runner；静态检查不能代替设备与执行验收。
