# ADR 0026：Root 录制与设备端独立 Runner 打包

状态：设计已采纳，2026-10-02；尚未声明实现完成。

## 边界

此项与编辑器“记录选择点位”不同：录制要捕获用户在其他应用中的真实触摸/按键，而非把编辑器点击伪装成录制。RootDaemon 的结构化协议负责读取白名单 input 设备，不能把 getevent/shell 字符串交给 Lua。开始/停止必须带随机会话、最大时长和事件预算，停止走优先通道；运行和录制互斥，取消不提交草稿。

手机 APK 打包不能只生成 ZIP 后改扩展名。使用无编辑器依赖的预编译 Runner 模板 + 冻结 Lua/资源发布目录，保留合法的已编译 AndroidManifest，重建 ZIP 和 APK 签名；首个实现不重写固定模板manifest。密钥在设备私有存储/KeyStore，不能签入仓库。Studio 工具链可编译 Flow，Runner 始终不携带编译器。应用包名、版本、能力、摘要、UI 与资源都在构建后验证，不导入参考产品二进制或远端打包服务。

## 实施和验收阶段

1. Root 事件解码：设备能力枚举、轴范围/方向映射、单指生命周期、有限轨迹、按键白名单、溢出与多指拒绝；主机测试先行。
2. 生命周期：协议/服务/客户端开始、停止、取消和故障收尾，断连/超时不保留按下态。只在真实后端就绪后打开录制入口。
3. 草稿转换：等待、点击、长按、滑动/拖拽、按键转换为现有积木，预览后一次加入，可撤销。
4. 发布准备：复用 release-packager 的冻结与资源校验，应用配置快照不可变，取消清理暂存输出。
5. 模板与签名：只打包固定独立 Runner 模板，保留已编译manifest、ZIP/ABI 对齐、设备签名；有真实验签结果才标记APK构建成功，安装/设备密钥另行验收。
6. 隔离验收：安装为另一包名，运行/UI/暂停/停止验证，升级保留数据，Studio 不卸载不清数据。

录制仅在真实后端就绪后开放，尚未实现的能力保持明确不可用。设备打包入口须执行实际冻结、签名与复验，任何一步失败都不能写成功日志；UI、方案、解码测试均不等于真实录制/真实 APK 构建完成，主机签名算法验收也不能替代设备KeyStore及安装运行验收。

2026-10-02 录制阶段 1–3 实施：Root 私有协议增加能力协商的开始/优先结束命令与有界 evdev 工作者；Studio 仅在实际后端就绪时开放入口，开始成功才隐藏窗口，REC 浮窗可跨应用停止/取消，有界一次结果缓存。沿用项目 input.basic 声明，不新增 Lua API；曲线/超长/过短手势单独跳过并显式预览，损坏、多指、溢出整批拒绝。草稿一次加入最多256积木。详见 [Root 录制实施与设备验收边界](../guides/root-input-recording.md)，真实设备验收仍单独记录。

2026-10-02 打包最小实施边界：设备端固定模板 applicationId=com.autoscript.runner、versionCode=1、versionName=0.1.0、桌面名称与图标，不提供伪可编辑的自定义选项。脚本项目名与 UI 来自冻结清单。Studio-only compiler JNI 复用 release-packager；重建 ZIP 中原生库 STORE 且16KB对齐，使用 AOSP APK v2 的 RSA/SHA-256 签名与分块摘要。密钥由 AndroidKeyStore 生成并长期保留，私钥不可导出，不添加生产依赖。构建在私有暂存目录执行，有取消/120秒截止且失败清理，不覆盖已有 APK；输出交由 Studio 导出/分享。主机独立 apksig 验签及包结构验证是算法验收，设备密钥与安装运行验收另行标记，不能由主机测试推定已通过。

本批新增识别预览/取消与录制AIDL能力，Android运行协议升级至v21，旧v20服务由既有版本握手明确拒绝。新增AIDL方法只追加在原方法之后，保留已有事务编号；project/Flow/node/API版本及持久化标识不变，也不影响独立Root认证协议。输入特性增加具名INPUT_FEATURE_RECORDING位，不用界面硬编码猜测后端能力。

设备打包模板使用独立Runner的非debuggable release变体，但原生库仍沿用开发构建配置，并未完成包体优化。模板预算512MiB、最终APK预算1GiB，暂存空间预检约三份APK大小。固定包名意味着同设备的新项目替换旧Runner；生成前比对现有安装证书，不同证书明确提示不能原位升级，绝不自动卸载或清数据。项目冻结复用ProjectStore既有只读清单规范化，逐块校验权威源码和清单一致，不引入额外迁移或备份恢复。
