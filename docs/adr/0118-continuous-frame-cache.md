# ADR 0118：Root 持续帧缓存与新鲜度边界

日期：2026-10-17，阶段1执行中。

## 决定

- Studio/Runner 的 Root 视觉热路径增加独立的有界帧缓存，最多保留 3 帧、总像素预算 32MiB；缓存条目携带原始 `FrameMetadata`、屏幕代次和单调时间戳。
- `Screen.capture()` 只有在宽高、方向、屏幕代次一致且帧年龄不超过 80ms 时才允许复用；时钟回拨、几何变化、代次变化或超龄均强制走现有 Root 截图路径。连续帧系列不复用缓存，仍按系列节奏真实采集。
- 缓存命中使用 `Arc<[u8]>` 共享像素，不复制整帧；发布到 `FramePool` 仍生成新的任务帧身份，租约、释放和原有 Lua/API 语义不变。
- 输入派发、停止、取消、Root 断开/重连、项目显示代次变化和会话关闭都会清理缓存。缓存失效或缺失不报错，自动回退兼容截图路径。
- 运行观测显式标记 `continuous-frame-cache` 和缓存年龄，禁止把缓存命中伪装成 Root 采集耗时；未测量前不宣称达到 100ms 端到端目标。

## 不变范围

Root 鉴权、协议线格式、截图像素、方向、阈值、模板匹配顺序、FramePool 租约和项目格式不变；不新增 Lua 函数，不自动截图，不改变处理坐标语义。

## 验证

先运行 `engine-jni` 与 `automation-core` 单测，覆盖缓存年龄、代次/几何隔离、时钟回拨、容量和失效，再编译 Android JNI。真实设备性能需用同一设备、ROI、模板和至少 100 次样本单独验收。
