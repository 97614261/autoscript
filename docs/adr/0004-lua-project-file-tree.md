# ADR 0004: Lua 项目文件树与模块装载

## 状态

已接受（2026-09-21）

## 背景

易编精灵的 Lua 编辑器不是单一文本框：项目有受限的 Lua 文件目录，可创建子目录和模块，并从已保存的指定 Lua 文件运行。Studio 现有模型只允许根目录 `main.lua`，导致标题中的“文件”入口无法承担真实文件管理，新增文件也不能进入备份或运行链路。

## 决策

1. 项目清单增加可选 `luaFiles`，记录 Lua 项目权威文件的相对路径；入口 `entryPoint` 必须属于该列表。旧项目缺少该字段时，按其现有入口补齐，保持 `main.lua` 兼容。
2. Lua 文件路径只允许 `main.lua` 或 `lua/` 下的 `.lua` 文件；不允许反斜杠、空路径、`.`、`..` 或隐藏目录。`luaDirectories` 记录受限目录（包括空目录），以保证备份与恢复后的文件树一致。
3. Project Store 提供创建目录、创建 Lua 文件、读取和按路径保存 Lua 文件的事务 API。所有操作都在项目根内做 canonical-path 检查，写入大小受限并使生成产物失效。
4. 备份、导入和打包以 `luaFiles` 为清单：未声明的文件不导出，导入时拒绝额外 Lua 文件。
5. Runner 继续只接收一个 Lua 模块。Studio 在启动前将已声明模块包入受限的 `require` 装载器；模块名由 `lua/foo.lua` 映射到 `foo`，入口仍按原 Lua 入口协议返回任务函数。此装载器只读取本次冻结的内存模块表，不暴露宿主文件、Shell 或 Android API。

## 后果

- 标题可成为真实的文件管理入口，右侧首位可保留给项目变量维护。
- Lua 模块的保存、恢复、备份与运行行为一致；未保存的当前文件不会被误运行。
- Schema、Rust Project Manifest 校验、Project Store、运行计划和编辑器必须同步升级并覆盖测试。
