# ADR 0045：按启动入口恢复窗口

日期：2026-10-05。状态：接受，用户明确要求实施。

## 决策

- 项目列表启动有设计界面的项目时，由 Studio 独立前台悬浮服务保留配置 View、已确认参数和启动任务。参数校验后立即隐藏；编译与 Root 就绪检查仍照常执行。终止、失败或连接丢失后恢复该配置窗，重新运行重新编译，不复用失效产物。
- 编辑器运行保持直接执行，终止后恢复编辑器，不弹脚本配置界面。返回监听必须由自己的启动请求显式授权；初始、陈旧或其他入口的状态不能触发回窗。
- Studio 同时只开放一个编辑或配置会话，切换入口先关闭原会话。关闭配置会话不隐式停止脚本，启动准备任务可以从通知取消。
- 用户最新澄清：点编辑只展开编辑弹窗；最小化后才显示吸附球；点球或恢复编辑时展开原窗并隐藏球。球和编辑窗分别使用有界系统窗口且互斥显示，禁止用包含二者的透明大矩形拦截其他 App 的触摸。运行/选点/截图/系统授权期间编辑窗和编辑球一起隐藏，运行控制球继续由运行服务拥有。
- 共享传统 View 渲染器及 Runner 的先配置再执行保持不变；不把 Studio 编辑或配置服务加入 Runner。

## 证据和区别

一键玩 `developers.startScript`、`FloatingInterface.outRunStop` 保留并恢复配置界面；编辑分支使用 `createCreateScriptWindow/showCreateScriptWindow`。易编新版有独立 `VisualUiPreviewService` 和 `stop_return_entry` 设置。原一键玩展开编辑时隐藏球；用户最新澄清采用相同互斥显示方式，取代此前编辑球常驻的决定。

## 边界

Intent 仅传项目标识，不传用户源码或参数。内存会话不进入备份；已确认参数沿用项目隔离的私有配置存储。服务非导出，不自动授予悬浮权限。启动有超时和取消，失效回调不能重开已关闭窗口。测试覆盖授权返回、重复结束、陈旧通知、取消和会话冲突；设备交互由用户统一验收。

## 2026-10-05 编辑入口修正

展开状态统一由悬浮会话持有，Compose直接观察，不再将本地旧状态通过SideEffect回写服务。恢复先由服务更新原生窗口可见性，不等待隐藏窗口绘制。已有同项目会话时，项目行展开和“编辑”恢复保持可用；启动、删除等工程变更仍禁用，不允许以恢复为由切换项目或绕过配置会话。首次挂载先设置完整虚拟画布，并在原生View附着后重新更新窗口。
