# ADR 0167：找色备选色组与紧凑配置

日期：2026-10-27

## 决定

在找色、比色、颜色计数、查找全部颜色的既有积木与 Screen API 上增加可选的 `additionalColors`，不新增另一套单色积木。主色仍使用 `rgb` / `tolerance`，附加色为 `RRGGBB:tolerance`，以分号分隔。最多16色，每色容差0–255，附加文本最多164 ASCII字节；重复颜色、非法格式与超预算拒绝。

这是“任意颜色命中”的 OR 查询。每个像素只读取一次，逐色比较消耗既有比较预算；命中后不再比较余色。重叠容差不会重复计数或返回坐标，数量上限、区域、搜索次序与帧所有权保持原接口语义。多点找色仍是有相对位置约束的模式，不改变为 OR。

缺省或空色组保留原宿主参数数量与单色路径。非空色组需要 runtimeApi 1.8，生成 Lua 显式检查 `Screen.colorGroupVersion == 1`；旧运行时不得悄悄只识别主色。正式保存/打开和 JNI 内存草稿复用原版本提升事务，不放宽编译门禁。

## 界面

色组使用可点选的色块、单色RGB与独立容差输入；屏幕取色替换当前选中的色位，打开取色工具期间保留未保存色组。不展示冗长原始串，积木概要显示色数和“任意命中”。

找色、比色、计数、全部颜色、取色、多点找色和结果读取使用紧凑单页，不再分三个标签页。参数、输出、暂存帧和必要覆盖确认同页可达；横屏或键盘占位时主体滚动、标题和提交固定。复杂模板和 OCR 保留分区。范围合并显示坐标与宽高，避免四个窄按钮截断数字。

共用编辑面板缩小标题、操作条和外边距，说明按需展开。新弹窗初始焦点落到容器，搜索框和输入框在用户点选后才获得焦点；重组不反复清焦点，不改变显式新建文件夹等用户触发的输入操作。

## 验证边界

定向检查覆盖解析/预算/重叠去重、真实 Lua 宿主调用、编译及版本门禁、配置往返和项目保存。检查实际结果记录在 AGENTS.md。首轮按用户要求仅安装 MuMu；随后用户明确要求打包线上，以0.1.24/versionCode25沿原双架构和签名 HTTP 流程发布。不连接真机或运行私人脚本，主机检查和发布核验不冒充设备功能验收。
