# ADR 0033：有界多图结果及类型化属性读取

状态：采纳。日期：2026-10-03。

新增原生多结果模板匹配，既有 Screen.findImage/findImages 的首结果语义不变。新 Screen.findAllImages 按调用者的模板优先级及当前方向枚举位置，共享像素比较预算和5秒取消/超时；1–64模板，1–64结果，额外探测一项确认截断。不得把限定数量伪装成完整总数。无匹配返回空集合，非法输入、取消及预算耗尽为错误，不转成未找到。

结果为有版本的有界UTF-8 JSON字符串，明确区分屏幕帧句柄和结果集合；每项含x/y、width/height、scorePermille、path，另有count/truncated。采用现有字符变量保存数据，不新增任意宿主对象、指针或执行能力。Screen.matchValue按白名单属性读取JSON标量编码；可视化vision.result负责按属性转换为整数或字符目标变量。越界索引拒绝，不返回伪造坐标。

新积木vision.findallimages和vision.result可在智构图像入口、函数库加入和修改；Schema及编译器严格检查声明、能力、模板资源和结果数量。冻结Lua与Runner共享能力。自动截图只拥有自己取得的帧，在正常/异常路径释放；借用帧不释放。结果不含像素，不经过AIDL高频传输。

这是新版明确的匹配契约，不认定与旧Native算法等价。旧阈值、重叠消除、搜索顺序、滤色和结果属性必须另有证据；未确认项原稿保留并阻断。每阶段补合成实际执行测试，不能仅补目录入口。

匹配后动作：默认无动作；可选点击、按下、点击后等待、按下等待弹起。默认只操作首结果，也可遍历保留结果，但持续按下不允许遍历，避免占用同一触点。偏移按原始屏幕像素计算；操作时间1–5000ms，前后等待0–60000ms。前等待在截图前，拥有的帧在动作/后等待前已释放；无匹配不触发动作。需要输入或等待时显式检查input.basic/core.task，不给工程静默提权。
