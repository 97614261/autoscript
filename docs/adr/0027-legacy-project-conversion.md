# ADR 0027：旧一键玩工程的离线、保守转换

日期：2026-10-02。状态：第一阶段实施，完整执行语义对齐未完成。

## 决策

使用无新增依赖的 Python 命令行工具读取用户提供的 ZIP；遵循旧 Java 源码的 CRLF、制表符树和 `┊`/首个冒号字段规则。不执行 ZIP 内的脚本、DEX、APK 或外部插件。所有私人原稿、转换报告和产物只放在忽略的 `build/legacy-conversion/` 下，不写入仓库样例或普通日志。

后续 ADR 0028 提取独立 GUI/CLI，输出改为用户选择的全新目录（默认工具 output）；仓库验证仍放忽略的 build。旧入口保留包装，原稿与报告不得进入源码/普通日志的限制不变。

第一阶段只迁移已确认语义的积木及 BI_RGB BMP 图片。未确认的指令/分支/类型保留原始记录和树结构，使用未知节点显式阻断编译，绝不替换成能运行的空操作。缺失入口、未转换界面、分组、外部插件也列为阻断项。仅没有阻断项的候选工程生成 `.asproject`；仍须经过当前编译器验证才能宣称可运行。存在阻断项只交付审阅草稿和报告。

变量上限从256提高到512（仍有界），同步 Rust、Kotlin、JSON Schema 与边界测试。旧寻图结果对象并非屏幕帧，不能直接冒充 `image` 类型；保留在报告，等结果对象访问语义接通再转换。此次不改变 UI 控件上限、不加载外部二进制、不放宽宿主能力白名单。

## 安全与恢复

ZIP 路径、重复项、符号链接、大小、数量与 UTF-8 均验证。新输出使用临时目录完成后发布，不覆盖既有目录；出错保留临时目录供排查。完整原 ZIP 以原始字节备份，不改原文件。转换结果标识和变量名稳定映射，报告包含源文件、行号和原因，但终端只输出汇总数量。

## 未完成

旧 UI、找图成功/失败分支、C++式表达式、返回状态、复杂输入及自定义函数的等价迁移是后续阶段。用户提供的真实工程存在这些项，第一阶段产物不是可直接运行的最终脚本。
