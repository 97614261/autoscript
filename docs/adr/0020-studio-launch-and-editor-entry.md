# 0020：区分项目启动与编辑器运行

状态：已接受（2026-10-01，用户最新决定）。替代 0019 中 Studio 普通运行统一先打开脚本界面的约定；独立 Runner 的启动顺序不变。

## 决定

- 项目列表的「启动」：有已设计界面时先显示它，确认运行后再执行脚本；关闭不执行。没有界面时直接运行。
- 编辑器的「运行」：保存草稿、验证/编译并直接执行当前插件，使用界面默认配置，不打开启动配置窗，也不进入自动生成的界面事件循环。单步仍使用独立检查点路径。
- 可视化「编辑」：在项目列表上直接展开已有编辑弹窗，不先展示旧全屏程序树。最小化才收成吸附球，关闭返回列表。
- 继续使用 VisualProjectScreen 的编辑状态、持久化和工具回调，不换成另一套旧编辑控制器。旧全屏节点 ID、orderKey、编译诊断界面不作为用户编辑入口；诊断仍通过编辑弹窗反馈。

## 兼容与边界

不改项目/插件协议、已有数据、Runner 模块依赖或 Root 后端。直接运行复用现有编译器的 `__ui_debug_skip_events` 开关，不通过单步实现普通运行。共享运行界面的能力和独立 Runner 流程保持不变。

## 2026-10-02：确认后不自动重开界面

Studio / Runner 已在启动前显示并收集配置；确认运行后，运行服务只激活界面事件和隐藏的 View 控件，不再次添加运行界面窗口。过去在 `nativeStart` 后直接显示运行界面，会造成配置窗关闭后闪现另一份界面，短脚本结束时又清理它。显式 `UI.command("window", "show", "")` 仍可显示运行界面；隐藏期间 `UI.setValue`、页面切换等更新继续作用于保留的控件，后续显示时沿用更新后的状态。编辑器直接运行及单步行为不变。
