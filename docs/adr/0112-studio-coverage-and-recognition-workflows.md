# ADR0112: Studio 功能总账与识别流程一致性

2026-10-15。用户授权执行总计划第1–3阶段。仅开发、源码/回归源码编译及静态检查；测试执行、Lint、APK和设备验收后置。

## 决策

- 当前总计划和逐项积木矩阵作为待办真相；历史批次记录保留当时事实，不把历史“未实现”重复列为当前缺口。静态契约、编译器登记、入口及源码表示证据与实际运行通过分开记录。矩阵生成器明确不能证明每个参数的运行效果。
- 保存图片的像素/灰度测试和回填共用不可变配置，范围采用原图半开矩形，像素搜索方向原样回填。灰度不接受方向或颜色容差，不静默切算法；当前测试只支持单张模板，不冒充已测试目录或多结果行为。处理工作台复用同一配置。
- 修复预览服务丢弃像素方向的内部链路；沿用八整数options末位传现代0–4方向，字库末位仍为原空格间距。保留旧JNI签名，另加内部有界配置入口，不新增脚本API或修改Binder协议；预览保留既有预算/期限，不保证下一次正式运行成功。
- 图片测试证明绑定来源位图、完整参数、模板和运行会话；输入、资源或上下文变化后失效。取消和截图交接保留原配置，不发布迟到结果。保存保持原像素及既有资源预算。
- 更新ADR0111的字库等待规则：非空及完全一致保留原门控；非空目标的“包含”使用同一截图的真实逐字结果和既有Ocr.findText，只匹配同一行连续已识别字形。区域其他未知字不再否决目标，目标内部未知字及跨行不通过；不含空白的目标最多256字节。完全一致仍要求覆盖率1000‰并比较完整文字。
- 包含模式一次OCR生成逐字数据，通过专用读取同步原文字、覆盖率、得分，两个额外字符工作变量分别保存逐字结果与目标匹配集合，必须声明、类型正确且互不覆盖。不能调用普通OCR后另截新帧或用未知问号代替真实字形状态。原非空/完全一致的输出和旧已保存组合不迁移。
- 等待配置集中显示条件、常用时限和变量状态，工作映射折叠且可以明确确认快速分配。分配保留有效已有选择，不覆盖原识别引用，维护变量返回保留草稿；总期限仍在调用前后检查，不承诺SDK硬实时抢占。
- 结果读取和动作给出形状/生产积木/类型说明；已有帧与处理坐标不自动推断为原屏。动作配置改变位置、来源等相关条件清除旧确认。无新API、协议、算法或模型。

## 验收边界

177种积木矩阵不等于177种积木已设备验收。源码往返/生成数据/字库未知字和字框布局的回归源码先补齐并编译，集中测试阶段再运行。第4–8阶段、独立Runner和下载器不计本次交付。
