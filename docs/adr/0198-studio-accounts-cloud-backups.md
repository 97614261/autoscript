# ADR 0198: 账号登录注册与脚本云备份第一版

日期：2026-10-30

用户要求先做登录注册和脚本备份。后台使用已同步上游的 `ruoyi-go` 仓库，分支为 `codex/zhigou-admin`，基线 `39bc60f`；App 沿当前 Studio 接入，不改变脚本运行协议。

- 项目页“备份 → 服务器备份”进入账号页，支持服务器地址、注册、登录、退出和重新登录。会话及每账号备份密钥用 Android Keystore AES-GCM 保存，密码不持久化，系统备份排除沿用原配置。过期会话或服务端 401 返回登录页；无法清除本机登录时提示手动退出。
- 登录后支持列表、新增快照、覆盖指定备份、下载恢复及确认删除。备份包含已保存脚本和项目资源，不包含编辑草稿及运行值；复用原 `ZGBK0001` 加密、项目导出和完整导入校验，恢复为新项目，不自动运行或覆盖本机项目。覆盖及删除绑定列表摘要，拒绝过期操作。
- 抽出 `BackupTransport` 复用现有备份界面和事务。新账号模式不改原个人密钥配置，“旧备份”仍访问旧服务；旧备份不会自动归属新账号。服务器地址不预置旧个人密钥服务地址。
- 新增 `/api/studio/v1`、独立 `zg_account/zg_script_backup` 表及 Studio Redis 前缀。账号与若依管理员、JWT、权限和旧表分离，注册不会获得后台权限。功能默认关闭，部署显式执行增量 SQL 并开启；既有用户修改的 `CLAUDE.md`、`configs/application.yml`、`aaaa/` 保留。
- 后台以登录身份限定所有备份读写，不接收客户端指定 owner。密码 bcrypt、账号错误限制及 IP 限流、认证和上传并发限制；随机不可变私有文件引用、大小/摘要校验、账号行锁保护配额、摘要 CAS 防覆盖冲突。提交确认丢失保留文件，不能按时间直接清理未核对的残留文件。
- 每账号独立随机备份密钥存于数据库，服务器管理员可取得密钥；本版不声称对服务器保密的端到端加密。默认系统 HTTPS 及证书校验，拒绝跨站重定向；HTTP 仅在登录页明确勾选调试后允许，界面提示账号密码明文传输。
- 第一版不含短信、找回密码、付费套餐、激活码、独立 Runner 授权、账号后台管理页或旧备份自动迁移。

实际验证：后台3项主机测试及24个真实本地 MySQL/Redis 接口场景通过，覆盖双账号隔离、精确文件往返、CAS、容量/份数、退出撤销、禁用账号、错误锁定和并发上传配额；随机临时数据库及本轮 Redis 键已清理，没有清理若依业务库。证据 `build/zhigou-backend-final-tests.log`。Linux amd64 目标 `go vet` 和服务构建通过，产物 `build/zhigou-server-linux-amd64`；本机 Windows/386 静态检查受原 `cmd/perfseed` 的大整数溢出阻断，未改用户学习目录或既有压测工具。

Android 新协议8项和原备份19项共27项 JVM 检查通过，生产及单测编译通过，证据 `build/studio-cloud-android-tests-2.log`。过期会话返回登录页的最后调整仅补增量生产编译，不重复整套逻辑测试。测试使用公开自有数据和本机协议服务；本轮未进行设备实际 UI、横屏、键盘或 ARM 功能验收，不能将主机检查记作设备通过。

本轮未部署服务器、改线上配置或密钥、升版、生成新 APK、安装设备、发布或提交 Git。线上仍为原 0.1.34。正式使用前按后台 `docs/STUDIO.md` 部署新 Go 服务及两张表，再在 App 配置账号服务地址。

用户随后要求“本地数据库和本地测试”。新增 `studiodev` 初始化及本地启动脚本，只使用本机 MySQL 和 Redis；独立 `zhigou_studio_local` 数据库仅借用原库表结构，无原用户、参数或任务数据，Redis DB14 首次要求为空，不清库。忽略的 `configs/studio.local.yml` 保留连接配置，`bin/studio-local/` 保存标记和私有文件；重复初始化确认配置摘要、测试账号不变。服务在 `127.0.0.1:18080` 启动，原服务器配置和默认监听行为保持兼容，后台进程的启动/停止按本仓库程序路径校验 PID。

MuMu0/API32 保数据安装本地 Debug 候选后，真实组件对接生产 Go 进程、本机 MySQL/Redis，完成9项实际操作：UI注册登录、Keystore加密及重开保持、已保存脚本与PNG上传、覆盖只留一份、恢复新项目并核对脚本及图片字节、第二账号隔离、退出撤销、服务端401返回登录、删除保留本机项目。全部通过且cleanup=true，证据 `build/function-usage-cloud-20261030T231214.log`。独立账号偏好/Keystore与缓存项目避免改写用户账号设置；不运行任何脚本。首轮 MuMu vk/auto 在EGL初始化阻塞，线程栈确认 `libEGL_emulation` 的 `HostConnection::connect`，该轮未记通过；沿用户既有临时切换授权改用dx/auto后完成，冻结自有项目经原内容检查清理，首轮独立缓存另核对确切ID/名称/资源后清理。恢复环境结果及最后标题布局另记，不能宣称横屏/键盘或ARM验收。

最终收尾：账号名移入正文，登录/备份标题不再被长账号挤占；仅补注册登录及会话重开2项布局检查通过，cleanup=true，证据 `build/function-usage-cloudLayout-20261030T232309.log`，720×1280两张实际截图标题完整。最终保数据安装的0.1.34/code35 Debug x86_64为73141410字节，SHA256 `de96d6664850fdafa4867a07aae1c8c783436691ef29682d6d675c15246e9685`，记录 `build/studio-local-final-candidate.json`；未生成或替换线上Release。

MuMu0经官方管理器关闭并恢复vk/auto，回到测试前关闭状态；关闭前搜狗IME、自动旋转1与方向0均与原值一致，记录 `build/studio-local-environment-restored.json`。本地Go服务继续运行且只监听127.0.0.1:18080，健康检查MySQL/Redis均up。用户可在后台仓库运行 `scripts/start-studio-local.ps1 -Background` 或 `-Stop`，App本地使用需在模拟器启动后重建adb reverse并显式开启HTTP调试；未部署、发布、升版或提交Git。
