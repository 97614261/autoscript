# ADR 0205: 随机设置下的生成物提交修复

日期：2026-11-04

用户报告闲置后运行出现 `COMMIT_FAILED` / `InvalidBundle("payload generationId does not match record")`，重启 App 仍失败，随后怀疑 Root 断开。首次排查只修复本地代码；2026-11-05 用户随后要求“打包线上”，实际发布结果见末节。

## 已确认的问题

编译器在项目随机策略生效或存在节点随机覆盖时，会在 Lua 正文前插入随机辅助代码。原实现将辅助代码写在生成标识之前，而生成物提交校验严格要求文件以两行生成标识开头，导致合法编译结果在提交阶段被拒绝。项目及节点配置持久化，重启后重新生成仍会触发；不依赖 Root，也不由空闲时间直接触发。

新增真实临时项目回归首先复现完全相同的错误，两项失败日志保留在 `build/generation-header-reproduce.log`。

## 修复

- 在渲染入口先写原两行生成标识，再写可选随机辅助代码和原运行前导。普通项目生成顺序保持原样；随机辅助的词法作用域和脚本执行语义不变。
- 保留原提交校验、摘要绑定、锁、暂存及原子替换，不用忽略校验或清理用户项目绕过故障。正常重新编译会从持久化源码重新生成，无需读取旧的异常生成物。
- Root 代码核对发现原连接在 300000 ms 无认证活动后释放，界面回到 STOPPED，不主动后台循环调用 su；用户运行、截图或明确连接时按需请求。当前编辑器先编译后调用运行入口，编译失败会使本次流程尚未到达 Root 连接步骤。本轮未连接用户设备，不能据此确认用户实际断连事件就是空闲释放，未更改连接超时或授权策略。
