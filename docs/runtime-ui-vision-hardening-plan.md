# 运行、界面联动与识别加固（2026-10-02）

用户授权执行三批：运行稳定性、设计界面联动、Rust/输入取消/图像识别链路。不修改现有 UI 风格，不扩展免 Root、云端、AI、动作录制或手机端打包；不以主机测试代替设备验收。

## 第一批：启动和控制

- 已实现：同一客户端一次仅允许一个启动事务，不排队重复启动；Root 等待、资源准备及实际提交绑定同一服务和会话代次。Root 已就绪但引擎状态未知时仍等待。
- 已实现：停止/断连取消客户端尚未完成的启动；取消和失败清理已准备资源，清理请求保持原会话代次，不影响替换后的会话。此保护覆盖进入 RuntimeClient 的启动事务，不新增保存/编译阶段的取消按钮。
- 已实现：可视化编辑器暂停、继续、停止失败显示当前原因，异常后释放界面忙状态；现有单步防重状态机保留并回归。

## 第二批：界面联动

- 已实现：控件值、可见性、启用状态与选项由独立状态保存，隐藏/非当前页更新不丢失；脚本更新抑制用户事件，失败时也恢复更新标志。替换选项保留合法选择，否则回退首项。
- 已实现：页面导航仍向宿主同步控件值和绑定；旧窗口清理的延迟回调检查代次，不得清理新界面；确认运行不自动重开界面的既有约束保留。
- 已增加：隐藏更新、选项同步、非法输入不污染状态、重置及启动/显式显示/过期清理回归，保持控件和节点 ID、绑定及持久化协议兼容。

## 第三批：Rust、输入与视觉

- 已实现：视觉适配器关闭时取消推理，等待当前任务退出再释放模型会话；关闭后拒绝新任务，调度失败也执行资源清理。JNI 响应严格校验状态、长度和错误码字符，拒绝任意 Java 消息进入错误码。
- 已增加：直接缓冲区容量、剩余长度、步幅、像素格式和上限校验回归；现有 ROI、灰度/OCR 解码边界回归通过。保留灰度找图与 A–Z/a–z/0–9 单行 OCR 范围，不新增识别模型。
- 已回归：Rust 输入仲裁、取消、资源释放与 UI 事件执行，全工作区测试通过；修复 API 契约测试仍以旧 42 项作断言的问题，实际 schema 为 46 项。
