# M27：完整 UI 整理与对齐计划

状态：UI 页面实现完成，验收中  
基线：M26 已通过主机门禁和 MuMu 回归  
目标设备：手机竖屏 720×1280；编辑器同时支持横屏和宽屏

## 1. 本批目标

M27 不再只实现“本地文件页”，而是一次完成当前本地 Root 阶段需要的全部产品 UI，使用户能从工作台进入项目、管理文件、编辑 Lua 或积木、设计脚本界面、配置运行环境、打包并在 Runner 中运行。

本批以 UI 与真实本地数据联通为目标，不新增视觉算法。M28 承接视觉能力补全，M29 再做全能力联调。

完成范围：

- M27.1 已建立统一设计 token、三栏主导航、首页和导航状态测试；
- M27.2 已建立真实项目文件目录与文件工作台，项目先进入文件页，再进入对应编辑器；
- M27.3 复用并统一现有 Lua/积木编辑器，文件项可定位到选定 Flow；
- M27.4 已把 Runner 动态表单从 JSON 作者入口提升为可视化字段设计、预览、排序和属性编辑；
- M27.5 已建立图片、截图与标注工具入口，并复用真实资源导入/删除；
- M27.6 已实现运行环境、备份管理、打包配置/更新/日志页面；
- M27.7 已整理 Runner 高级诊断和动作录制/悬浮控制页面；
- M27.8 已实现本地“我的”、登录边界、设置、法律说明和关于页。

项目的权威源码与资源使用规范路径，文件工作台不会提供可破坏 Schema 引用的任意移动/改名。Flow 新建与删除由积木编辑器完成，资源导入与删除由资源页完成；缓存、事务文件、备份和生成物不暴露为普通文件。

M27 只完成页面、交互边界和已有能力接通。尚无后端的手机端 APK 构建、动作录制事件流、在线登录和在线内容均显示明确禁用状态，不伪造成功；对应能力仍按后续阶段实现。

“全部 UI”指当前自动化开发闭环需要的页面，不等于照搬旧版的全部商业页面。旧版一键玩的代理、支付、提现、VIP、聊天、市场交易等页面不进入 M27。

## 2. 参考资料与采用原则

已核对：

- 易编精灵运行截图 45 张；
- 易编精灵页面候选布局 43 个；
- 旧版一键玩页面候选布局 98 个；
- 当前 Studio 的工作台、Lua 编辑器、积木编辑器、资源设置；
- 当前独立 Runner、运行通知和悬浮控制。

采用原则：

1. 视觉基线以新版易编精灵为主：浅灰背景、白色卡片、蓝色强调色、紧凑间距和明确的主操作。
2. 操作能力吸收旧版一键玩：项目文件管理、函数分类、录制入口、插件/分组管理和快速调试。
3. 不复制品牌名称、账号、服务地址、证书、商业图片和旧业务文案；图标和设计 token 在本项目内统一。
4. UI 不制造假能力。未进入当前阶段的在线功能显示“暂未开放/本地模式”，按钮不能伪造成功。
5. 页面只负责交互和状态展示，项目结构、运行状态和发布结果仍以现有 Store、Schema、Runtime API 为真相。

## 4. M27 内部实施批次

### M27.1 设计系统与导航骨架

- 固化颜色、字号、圆角、间距、分割线、按钮高度和页面标题规格；
- 统一竖屏页面壳、横屏编辑器壳、加载/空/错误/禁用状态；
- 建立显式页面路由和返回规则，移除用尺寸为零保活页面的临时导航方式；
- 完成首页、工作台、我的三栏导航。

### M27.2 工作台与项目文件工作台

- 重做工作台、新建项目和项目展开操作栏；
- 实现用户截图中缺失的本地文件页；
- 使用项目沙箱内的真实文件模型，不暴露任意系统路径；
- 文件操作通过 ProjectStore 执行，并维护清单、引用和生成物失效规则；
- 点击不同文件类型进入 Lua、积木、UI、图片或字库页面。

### M27.3 Lua 与积木编辑体验

- 统一保存、运行、停止、撤销、恢复、搜索和错误定位；
- 积木库按能力目录展示，完成变量、判断、模板、插件和分组管理 UI；
- 手机使用抽屉/底部面板，横屏和宽屏使用多栏，不强塞桌面布局。

### M27.4 脚本界面设计器

- 建立页面树、设计画布、控件库和属性面板；
- 支持标签、按钮、单选、复选、单行文本、多行文本、下拉列表等首组控件；
- 支持控件选中、移动、缩放、复制、删除、对齐、层级、撤销和预览；
- 保存到版本化 UI Schema，Runner 只读取生成后的冻结定义。

### M27.5 资源与图像工具 UI

- 独立图片/字库资源页和详情预览；
- 截图工作区、区域选择、取色/找图参数和图片处理/标注页面；
- 未实现的算法操作显示能力状态，不生成假结果。

### M27.6 运行环境、备份与打包

- 运行环境页显示 Runtime、Root、截图、按键、通知和悬浮窗真实状态；
- 备份管理提供创建、导入、恢复、删除及冲突提示；
- 打包页连接现有发布链，展示校验、构建、输出与日志；
- 在线更新页只保留本地配置结构，不接服务器。

### M27.7 Runner、悬浮窗与错误页面

- Runner 主页面面向脚本使用者，运行条件和底层标识进入可展开诊断区；
- 统一运行、暂停、继续、停止、失败、完成状态；
- 完成运行悬浮窗与录制悬浮窗的 UI；
- 错误详情可显示 Flow/node 或 Lua 行并返回相应编辑位置。

### M27.8 我的与预留在线页面

- 完成本地模式“我的”、应用设置、版本信息和法律文档；
- 登录/注册、学习项目和开发者后台提供明确的预留页面；
- 不实现后台管理、在线授权、收费、社区和免 Root。

## 5. 明确不做

M27 不实现：

- 免 Root、Shizuku 或无障碍执行后端；
- 真实账号登录、注册、云同步和远程凭据存储；
- 后台管理服务、项目收费、卡密、在线授权和热更新；
- 市场、社区、聊天、代理、VIP、充值、提现等旧版商业页面；
- 新的 OpenCV/ONNX/字库识别算法；
- 为了看起来可用而伪造下载、打包、备份或运行结果。

## 6. 状态与数据约束

每个有异步数据的页面至少覆盖：加载、空数据、正常、失败和重试。每个破坏性操作必须二次确认并显示具体对象。所有页面遵循：

- 项目文件只能位于项目根目录内，拒绝路径穿越和符号链接逃逸；
- `project.json`、Flow、UI Schema 和资源清单仍是权威数据；
- UI 不直接拼写运行协议或发布包；通过现有 API 调用；
- 文件名冲突、被引用资源、未保存内容和运行中项目都必须显式处理；
- 预留页面不得采集账号密码或声称已连接线上服务。

## 7. 验收方式

按用户要求，M27 内部不在每个小步骤构建。实现期间以静态检查、纯 JVM 状态测试和可预览组件为主；完成多个页面族后再集中构建一次并在 MuMu 上验收。

最终验收至少包括：

1. 720×1280 竖屏完整走通“工作台 → 项目 → 文件 → 编辑 → 设置 → 运行 → 错误定位”；
2. 横屏走通积木编辑器和脚本界面设计器，关键工具不裁切；
3. 工作台、项目文件页、Lua、积木、运行环境、备份、打包、Runner 均验证加载/空/正常/失败状态；
4. UIAutomator XML 校验关键文本、可点击区域、返回行为和页面路由；
5. 截图只用于密度、裁切、层级和视觉对齐，不代替日志与状态断言；
6. 真机不参与自动操作，设备脚本继续硬限定 `127.0.0.1:16384`；
7. 集中执行主机门禁和 MuMu 冒烟，并输出 M27 独立 JSON 报告。
