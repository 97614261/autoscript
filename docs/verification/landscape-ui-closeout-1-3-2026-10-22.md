# 横屏适配第 1–3 项收尾

## 范围与改动

- 仅使用 MuMu 0（API32 / x86_64）及新建的公开合成 QA 项目。未连接手机、不运行私人脚本、
  不更新网站、模型或默认 full 配置；不把模拟器结果记作 ARM 或原生手机验收。
- 查找替换改为单一有界列表，表单字段使用各自稳定身份的独立条目，匹配结果延迟构建；
  不再叠加固定的结果最小高度，也不把全部输入放在一个超长的焦点条目内。
  替换范围、确认、陈旧源码复核及撤销语义不变，关闭固定在共享面板。
- 取字配置/测试复用共享面板的实际剩余高度、键盘避让及紧凑标题，操作按完整按钮换行；
  配置、识别证明、取消和全屏还原保留原语义。
- 录制说明、状态、筛选及动作列表共用滚动预算，结果“下一步”位于滚动区外；
  录制能力检查、结果选择和加入确认不变，不为不支持录制的设备伪造结果。
- 修正 JNI 对尚未加载脚本的外部 VM 状态映射：更新屏幕或项目尺寸后仍为 IDLE，
  不再误标 RUNNING 并阻断截图。已有真实任务继续上报 RUNNING，停止/清理失败保护不放宽。
  新回归先在修复前实际失败（2 != 1），修复后覆盖新会话、重置、项目几何、真实运行和停止后的切屏。
- 测试增加独立 `landscapeOnly` 模式及键盘脚本 `-Suite landscape`，真实悬浮服务、真实触摸与
  明确启用的测试键盘共同验证。键盘仅来自 androidTest，不进入正式 App；脚本在 finally 中恢复原输入法并停用测试键盘。
- 共用组件夹具扩展取字、字库和录制准备窗的大字体横屏检查。此类夹具与真实悬浮宿主的结果分开记录。

### 设备限制

- MuMu 虽上报录制能力位，实际 Root 录制三次均返回 `UNSUPPORTED_DEVICE`：
  accepted=0、unsupported=3、cancelChecks=0。通过的是明确拒绝和后续运行恢复，
  不是自然手势采集/录制结果保存验收；录制结果布局已改为共享滚动预算，但本轮不冒充自然录制结果验证。
- 本轮未连接 ARM 手机、未替换 OCR 模型或默认 full、未发布网站或运行私人脚本。
  不将模拟器验收转记为其他设备、输入法或 API24 的完整验收。

## 初次失败及口径

- 横屏二级日志窗首轮点击等待失败；该轮未通过，随后同包复测再核对。
- 首个键盘用例依赖可访问“设置选择范围”动作，Compose 返回未接受；改为先清空 QA 输入框，
  由真实测试键盘输入 `QA`，直接检查输入结果和确认按钮边界，不以可访问文本注入代替真实输入。
- 查找替换在键盘下的滚动检查曾误取横向文本滚动区；后续真实触摸仍未稳定露出确认按钮，
  因此将整个表单的超长单条目拆为各字段独立条目，并固定滑动所在的已观测内容区域。
  每次失败保留日志和公开窗口截图，不计入最终通过。
- 首次录制入口用例遗漏 QA 工程的 `input.basic` 声明，被生产规则正常拦截；补齐声明后当前后端上报录制能力，
  真实录制准备窗的打开、说明、全屏和关闭通过。是否能够采集自然手势须看实际录制回归，
  不能仅凭能力位或准备窗通过宣称录制结果已经验收。
- 横屏截图首轮失败有固定诊断 `CAPTURE_RUNTIME_BUSY`，不是截图 Native 后端失败。
  修正空 VM 状态映射后，同条件诊断变为 `CAPTURE_READY`，参数返回断言通过。
  下一轮测试遗漏了修改参数后的放弃确认，停在正常保护弹窗；补齐显式确认，不绕过草稿保护。
- 系统编辑窗还原时，Compose 控件可先于 native 窗口边界更新；早期测试混用全屏旧边界，
  形成错误手柄偏移。最终用例先等真实小窗边界，再冻结实测手柄的右/下边距；
  MuMu 移动后的无障碍可见位及窗口边界也可滞后。最终在自有纯色背景上读取编辑窗实际渲染边界，
  无障碍位不当成功依据，必须真实触摸并观察到画面中的宽高改变。
- 额外数据安全测试曾硬编码新工程默认含一个空任务（45 行），与已批准的空新插件不符。
  改为实际基线行数加完整复制森林的节点数，仍逐一断言整批撤销、重做及源码无损往返，
  不重新插入空任务或放宽生产校验。
