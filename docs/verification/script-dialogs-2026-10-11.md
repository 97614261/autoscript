# 脚本确认与布局对话框 · 2026-10-11

依据：[ADR0066](../adr/0066-script-confirm-and-layout-dialogs.md)。使用：[脚本对话框](../guides/script-interface.md#脚本对话框)。

## 本批实现

- 三个真实函数与积木：确认框、布局框、关闭框，统一 ui.control 能力。函数库加入先配置，修改共用面板；受限源码使用生成积木契约往返。
- 确认框紧凑传统 View，标题居中，正文有界滚动，按钮居中；选择结果为字符变量，不把关闭映射为确认。
- 布局复用已保存页面、控件状态与图像资源；临时隐藏主窗，关闭只结束布局等待，保留填值并恢复原主窗状态；停止清理，不恢复旧窗口。
- 共享运行宿主的epoch、可取消等待、有界期限和窗口清理。长等待独立单线程和容量1的通道复用，不阻塞 Root 工作队列；关闭为控制消息，避免排在等待后。连续对话框可在前一完成通知收尾期间排入，真正重叠的请求仍拒绝。
- 严格编译检查页面、字段、文字字节预算、期限、字符输出变量和能力声明；不修改既有布局或项目结构。

## 手动验收

1. 函数库「界面」加入确认对话框，选择字符结果变量；分别验证确定得到`confirm`、取消得到`cancel`、返回/窗外得到`dismiss`，到期得到`timeout`。
2. 连续加入两个确认框，确认第一个后应立即出现第二个；停止脚本应移除当前框，不因迟到按钮回调再次展开。
3. 先保存一个设计页面，再加入布局对话框：填写控件、点击页面close动作或底部关闭，应继续脚本且保留填写值；读取页面参数获得对应值。
4. 布局对话框启用禁止窗外关闭时，窗外点击不关闭；返回键仍返回`dismiss`。关闭或到期恢复原主窗显示状态，主动停止不恢复旧窗。
5. 用独立任务调用关闭对话框，应结束等待而不停止脚本；检查窄屏、横屏、长正文和输入键盘下窗口是否仍有界可操作。

## 明确边界

同运行只允许一个交互对话框；并发属性宿主调用在交互占用适配器期间报队列忙，普通异步控件更新继续可用。编辑器直接运行仍跳过自动界面事件循环，布局自身close动作可直接关闭；不擅自启用插件事件循环。页面来自项目已保存runnerUi，不接受任意布局文件路径。
