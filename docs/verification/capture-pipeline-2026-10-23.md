# 全屏截图认证流水线续优

日期：2026-10-23。设计见[ADR0146](../adr/0146-authenticated-capture-pipeline.md)。状态：代码、质量门禁、最终精确包的MuMu性能两轮及编辑主线通过，已保留数据安装。流水线实验两轮收益不稳定，**默认不启用**；交付采用既有上游x86认证实现。实验包结果不冒充最终包性能，线上未改。

## 本轮范围

已实现可显式协商的流水线：常驻Root桥先验证固定BGRA原像素头，再按原60KiB认证包从管道有界读回并发送，移除该实验路径RootDaemon中的整帧暂存。没有新增生产线程或帧队列，软件Bitmap读回、颜色/Alpha、全屏几何及默认模型不变。区域读回/传输尚未实现，不以全屏后匹配ROI冒充区域采集。

两轮完整流程尾延迟不稳定，最终Android默认连接不申请`CAPTURE_PIPELINED`，继续原缓冲认证流，且有专用回归测试。可协商协议及故障测试保留，不将实验实现冒充默认生产提速。最终候选仅将现有sha2/asm扩展至Android x86_64，硬件指令检测仍由上游处理；无SHA指令时使用通用x64标量汇编，Windows不变。依赖及原MIT许可见[核对记录](../reference/root-authentication-dependency-review.md)。

新能力需同时协商stream/stage/transfer及pipeline。tag3初始消息只承诺身份和几何，tag4最终确认绑定身份、完整字节数、阶段耗时及包数；所有分片保留HMAC、序号、请求及连续偏移检查。最后一片须先完成桥尾部验证，客户端完整确认前不发布帧。旧客户端/服务端和screencap沿原缓冲流路径，不静默切旧端语义。

原五秒采集期限及停止令牌贯穿读回/传输，优先停止不排入普通工作队列。初始消息发出前取消释放该次桥状态与请求围栏；发出后失败作废连接，不重放、换帧或返回部分像素。故障、关闭及下一次新帧仍遵循原输入清理安全要求。

日志传输标记区分`authenticated-pipeline`与`authenticated-stream`，中文显示“认证流水线”。采集、管道及传输已重叠，分位数不可相加；发送编码计时扣除本次管道读等待，避免把等待冒充HMAC耗时。acquisition/bridgeReceive在流水线下包含下游背压，不与旧串行阶段按相加口径比较。
