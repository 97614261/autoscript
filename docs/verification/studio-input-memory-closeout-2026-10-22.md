# 输入、内存与固定字库收尾

日期：2026-10-22，验收续至10月23日。按用户决定执行1、2、3、4、6，第5项仅用当前ARM虚拟Android及MuMu；不以宿主原生/API24为本批前提，不冒充它们已通过。设计见[ADR0142](../adr/0142-bounded-input-hotpath-and-virtual-closeout.md)。

## 实现

- 普通点击优先复用已有ASI2常驻输入桥，顺序DOWN/UP；两事件前均检查取消，失败不重放、不转Shell补点。未确认UP保留不确定触点，优先停止继续负责清理；清理失败仍禁止输入。
- 协议3新增可协商的固定输入失败原因。新旧客户端、非法载荷与未协商响应分别测试；不记录坐标、Shell或进程原始输出，不放宽运行日志只存结构错误码的边界。
- 实际发现的定时器堆积风险：取消长定时器或已完成宿主超时可留下惰性堆项。新增/取消时超过活动项两倍加64则压实；10,000次取消24小时定时器的测试同时确认有效定时器仍如期执行。
- 截图短缓存仅保留实际会查询的最新一帧，原任务帧仍由FramePool所有权管理。Java复用显式小端IntBuffer批量编码；透明、末块及随机像素逐字节等价，不直接读取Bitmap原始存储，不以旧屏冒充新采集。
- 制字增加数字/大小写覆盖、显式26/62字符批量标注及首处差异/缺采字反馈。期望文字只评分，不参与识别、写回或自动纠错。ASGLYPH v1、资源/历史预算及默认full/V4均不变。

上述定时器和缓存修正是确定的源代码改进，但不被认定为上一轮约25MiB PSS增长的已证实根因。上一轮普通点击失败的具体异常仍没有充分证据，保留[原始失败与复测](studio-closeout-six-2026-10-22.md)。

### ARM长测内存

60个30秒间隔样本，Runner PSS首个230,368KiB、最后245,226KiB，最小223,815KiB、最大245,226KiB。首尾增加14,858KiB（约14.5MiB）；中点233,378KiB，后半程仍增加，不能宣布已进入平台期。Native PSS及Java/native/graphics细分在该虚拟系统均报0，属于不可得。Studio自身Native heap从7,932,712降至7,755,048字节，不代表Runner Native heap。

另作24次、约23分钟的只读Root采样：Daemon PSS始终26,868KiB，输入桥95,011→94,208KiB，采集桥134,141→136,227KiB；分别波动在26,868、93,351–95,663及134,141–136,413KiB。虚拟系统`ps`的RSS/VSZ存在不合理组合，原值仅作平台报告保留，不用于精确堆归因。首个采样器因旧Android `ps`列差异未匹配到进程，错误日志与修正后的`arm-root-memory-retest.log`分开，前者不算有效样本。

长测真实点击计数与命中计数一致、全程未未命中，原始测试包摘要 `0250fea75ce8613e208d8c6f46ad5c4a2f9ed7ab17877a1c8b42da15c76288e0`。比前轮吞吐提高不被当作公平分位数性能对照；首轮未定位点击异常也不因本轮通过而被删掉。

### MuMu长测内存

30个30秒间隔样本，Runner PSS71,248→78,251KiB（+7,003KiB，约6.8MiB），范围69,313–78,251KiB；中点71,656KiB，后半程仍上行。该平台Native分项可得，Native PSS27,522→33,086KiB；Java heap摘要8,444→10,624KiB，Native heap摘要27,500→33,064KiB。它们是平台进程内存会计，不等于尚未释放对象/实际malloc字节。

MuMu与ARM一致，有限时长内未出现业务停止或计数失配，但PSS不是完全不变。没有强制GC、定时重启、清数据或隐去末尾增长来制造平台期；仍不能宣布长期零泄漏。本批确定修复的定时器惰性堆项已有独立压力测试，其他增长不能从这组PSS直接归因。

### 字库专项初次失败与修正

新增覆盖信息改变了小窗内辅助文字的可见范围，旧夹具在画布缩放实际已成功后，等待视口外倍率文字而超时。截图取证明确显示宽度96→192像素；最终夹具保留真实点击，直接断言公开实心字形渲染宽度翻倍及适应后恢复，未改变生产缩放代码或减弱为按钮可点。

其间通用强制滚动导致待标注格子暂不可见、两种滚动接口不能定位辅助文字的尝试均失败，日志分别保留，不计通过。旧“不一致”文案断言亦更新为实际新增的“首处差异第3字”和“尚未采样：2”，增加了反馈内容核对。最终MuMu `mumu-glyph-complete.log`24/24，QA摘要 `6253aaa555cb80cec27646dcb941ba6adf98478b33601ce7e0c47b3e17904c48`。

ARM首轮及多次复测在双色字库的追加/测试步骤失败：QQ键盘存在时AX可见标志不能保证按钮实际可点，且显露请求后还有滚动/IME重排。夹具追加父容器/窗口/IME边界检查、显露请求及连续300ms稳定坐标要求，仍使用真实DOWN/UP，不隐藏键盘或改生产页面来放行。初次仅检查剪裁、只读文字与按钮未区分、仅显露未等待稳定的尝试均保留失败记录。

最终`arm-glyph-stable-bounds.log`24/24，QA `eb480cf9f6dfa2d8b5ba92fbb24a2482c73faade5e13e07ca532cd24086f3040`；同源码再编译MuMu `mumu-glyph-last.log`24/24，QA `63ab7658c465ee56da8edb43a3726596512df4672fd6ddc189ad849a58ceded3`。点击前自有公开截图确认追加按钮处于键盘上方；没有用AX直接触发按钮回调替代真实点击。

本批不改变固定字库分割/匹配算法，因此不能把制作流程更完整冒充综合字符准确率已提高。历史数字12/12、混合字母数字和`l/1`、`O/0`等失败仍见前轮报告；默认V4不替换。
