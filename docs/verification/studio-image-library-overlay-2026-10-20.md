# 图片库入口与资源列表修复

2026年10月20日。可视化编辑器的“图像 → 图片库”改为紧凑全页图片资源浏览器，默认显示所有子文件夹中的图片，点图复用现有处理工作台。不改变项目资源格式、识别参数或执行协议。

## 问题与修复

原入口接到了旧“图片与标注”截图工作区，而且只展示根目录的图片，导致项目有图片、列表却为空。之前修复了普通 Activity 弹窗与悬浮编辑器宿主不匹配的问题，但四项窗口测试没有覆盖页面职责和子目录内容，不能视为正确图片库的验收。

本批以 `ImageLibraryDialog` 替换该入口，仍用共享 `StudioDialog` 注册系统悬浮窗口。移除没有其他入口的 `ImageToolsScreen` 旧截图页及所属无用导入，截图操作复用编辑器现有显式截图流程，不自动截图。

图片库顶部使用小标题、计数和紧凑操作；列表显示缩略图、名称及所在目录，点图直接进入处理、识别测试和制字工作台。默认“全部图片”与明确选择的根目录分开，搜索同时匹配名称和目录，返回工作台前的目录和搜索保持。缩略图只在可见列表项按最多128×128解码，不改写原图片；工作台仍按既有原像素及内存预算解码。

导入直接选择存放目录，再调系统图片选择器，不跳项目设置。复用同一图片文档校验和 `ProjectStore.importResource`，冻结目标目录及资源集合；资源变化时拒绝覆盖。关窗取消所属协程，未发布的完整预览独立回收；不增加删除、移动或自动运行操作。
