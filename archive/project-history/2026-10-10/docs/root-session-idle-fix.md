# Root 持续找图时的停止通道误超时修复

日期：2026-10-09。决策见 ADR 0049。

## 定位依据

用户提供的 SCREEN_CAPTURE_FAILED / CAPTURE_BACKEND_FAILED 不等同于模板没找到。
排查环境为 MuMu x86_64、Android API 32、720×1280。日志中 Root 输入/截图桥建立后约五分钟关闭，失败前一秒仍有成功的快速截图；故障按 Root 连接生命周期出现，不按本次脚本启动时刻计时。

代码确认：业务和优先停止连接各自五分钟空闲超时，停止客户端平时按条件变量阻塞、没有流量。业务持续截图时，停止连接仍超时并把输入安全栅栏标记失败；随后 Capture 在进入实际采集后端之前即返回空 BackendFailure，客户端映射为 CAPTURE_BACKEND_FAILED。

这是一项确定的代码缺陷，与上述现象吻合；不据此声称所有厂商截图后端故障均由此引起，也不调整找图阈值或重试残缺屏幕帧。

## 改动

- root-daemon-core：可选共享认证活动时刻，单调递增；未完成握手维持独立期限，原单连接接口兼容。
- root-daemon：双通道使用同一时钟原点和活动对象。无包首字节的等待按剩余会话空闲期阻塞，超时后复查其他认证通道的活动。
- transport：收到首字节后，剩余长度头和载荷共用八秒绝对期限。EOF、半包超时、无效长度和连接错误不重新同步。
- InputFence：真实控制通道失败立即取消正在执行的token，拒绝后续请求；随后取消录制并复用释放指针/输入桥的清理流程。

没有添加Lua轮询、免Root后端、后台心跳、旧屏缓存、新依赖或协议格式变化。五分钟真实全会话空闲退出仍保留。

## 验证结果

- 新增13项确定性回归：30分钟模拟业务活动及迟到停止、全会话空闲、握手不借用续期、鉴权/重放/重复Hello不续期、单调时钟、失败栅栏取消、socket空等待续期、半包拒绝续期、绝对包期限、EOF/连接错误、中断读取和非法长度。
- Root相关四个crate：60通过、1显式性能测试默认忽略、0失败。
- cargo fmt检查通过；主机及Android x86_64 Clippy完成，既有非阻断警告仍在。额外-D warnings检查被旧录制/协议代码警告阻断，不作为通过项。
- build.cmd -Verify：1分18秒成功；五个Android测试模块571通过、1跳过、0失败。Lint无错误，34 Warning、16 Hint。
- arm64-v8a、x86_64与内嵌Runner构建成功；覆盖安装到MuMu 0号实例，应用数据保留。

没有执行用户私人脚本，也没有等待30分钟做设备实测。下一次用户复测应重新打开智构，持续找图6至10分钟后停止，检查是否仍出现该错误以及能否正常停止回原界面；若再次失败，用对应新运行日志区分真实采集后端故障与会话错误。
