# 精简日志与长时间运行交付（2026-10-09）

决策见 ADR 0051。此批主要解决截图/找图的重复长记录与写满后丢失后续明细；脚本主动输出的内容不自动删减。未执行用户私人脚本。

## 文件与界面

- JNI和引擎继续发送原版本1观测，在日志IO线程转换成文件版本2；脚本执行、鉴权和匹配语义不变。
- `conditions.jsonl` 存去重条件：插件/积木、算法、帧尺寸、ROI、模板尺寸、阈值、方向、结果上限、预算、超时及后端等。最多256项且256KiB，无法完整编码或预算不足时保留原完整事件。
- 高频样本只写 `v/c/s/u/t`（格式、条件、结果、微秒耗时、接收单调时刻）及可选 `a/x/m/w` 数值数组（采集、传输、匹配阶段、匹配工作量）。数组最后一项为存在字段的位图，显式null和缺项可无损区分；字段顺序集中定义在RuntimeLogEventCodec，不改变单位。
- `events.<20位序号>.jsonl` 最多8段、每段256KiB，写满轮转最旧段而非拒绝后续事件。条件表不随段删除，保留样本不会悬空。旧 `events.jsonl` 仍可读，不自动迁移或删除。
- 顶部“累计”使用已经处理的全部观测次数；表内次数及P50/P95/P99仅取保留明细。轮转后显式提示窗口口径。待写队列丢失、引擎丢失、旧通道限额、格式无效和写盘错误仍分别标记，不补造缺失样本。
- 历史“追踪/指标”中识图事件显示中文单行摘要，完整字段通过导出保留。统计指标、全屏和截图主表/传输明细布局保留。条件分组同时包含预算及超时，避免不同输入口径混合。

## IO和资源边界

运行服务使用独立进程；每运行的 `journal.lock` 文件用于跨进程共享读锁/独占写锁，获取期限1秒，锁文件本身为空。读快照同时取得条件、明细及最新元数据，避免部分行、条件尚未落盘或计数落后于所读明细。导出也取得同一快照锁。进程内串行锁只用于防止同JVM重叠文件锁，不替代跨进程锁。

停止、关闭与提示清理不等待日志IO；待写最多256条、单条8KiB。文件锁只由日志工作线程/读取IO使用，等待有界；不能取得快照时明确要求刷新。写盘失败在可写的元数据中尽力保存失败与终止状态，不把失败伪装成功。新运行不会复用旧条件表。

每运行默认最多2MiB事件、256KiB条件表、各1MiB脚本/诊断，最近16次历史；读取也受相同预算约束。轮转只删除本会话精确命名的旧事件段，历史清理只删已知文件，未知文件保留。所有路径检查规范化UUID子目录及确切文件名，符号链接不能跳出目标目录。

## 精简体积对照

合成720×1280 BGRA截图事件，带原始ID、后端、3基础/6桥阶段及6传输数值，同条件1000条；UTF-8字节（本例均ASCII），包括换行与首次条件定义。不是运行速度基准，ROI/模板不适用于截图事件。

| 存储 | 1000条字节 | 说明 |
| --- | ---: | --- |
| 原完整JSONL | 635000 | 每条重复字段名与条件 |
| 条件表＋紧凑样本 | 139291 | 条件只写一次，样本约139字节 |

此合成输入减少约78.06%；不同条件数量、ID、数值位数和可选阶段会改变比例，不承诺所有事件固定压缩率。没有牺牲任何阶段、状态或工作量。

## 认证调查

核对现有sha2 0.10.9：x86/x86_64已按运行时CPU能力选择SHA指令路径，否则走软件实现；现有热门crate已配置优化编译。本批不强制CPU指令、不换线格式或减少验签。

新增显式测试基准比较HMAC固定key预置内/外状态。Windows x86_64、Intel Core Ultra9 285H、dev热门crate优化、同一合成60KiB＋37字节包重复60次，预热10轮后100轮交替顺序，仅计HMAC，不计采集、封包复制、Socket和图像匹配；ROI/模板不适用。较空闲复测原实现P50/P95/P99为0.7852/0.8976/1.0067ms，预置为0.7851/0.8596/0.9103ms。中位收益近零，不将预置方案加入生产，也不据此推断MuMu的7ms鉴权一定可消除。

命令：`cargo test -p root-protocol benchmark_prepared_capture_authentication --offline -- --ignored --nocapture`。下一项真正的认证提速仍需目标环境的可信对照，当前没有冒充完成。
