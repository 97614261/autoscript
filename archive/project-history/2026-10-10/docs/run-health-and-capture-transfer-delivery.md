# 运行健康与截图传输交付（2026-10-09）

对应用户确认的后续计划1至4及 ADR 0050。不执行私人脚本，不将主机合成测试描述为 Android 实测收益。

## 交付范围

1. 日志总览复用已有信息行显示 ABI、帧尺寸、单调运行时长和认证 Root 会话年龄；主操作计数避免重复累加阶段行。Root 原会话失效冻结年龄并标记中断，旧日志缺项显示未知。运行中为已写观测快照，不新增定时刷盘任务。
2. 以推进时钟测试活动/空闲会话、短暂停顿、优先停止、新运行及新会话拒绝旧包。优先停止通道失效与采集后端失败使用不同固定失败码，保留停止独立通道、安全取消和指针清理。
3. 接收的 Vec 直接移动到私有不可变共享像素存储，去掉 Vec 转 Arc 切片的一次整帧复制。实际容量计入帧预算，帧序列拒绝超过预留的容量；只读租约、任务身份、独立新帧和已有 Arc 模板接口保留。
4. 将原“传输/鉴权”进一步分为发送封包/鉴权、发送写出/背压、接收等待/读取、接收验签/校验、像素追加及包数。主截图页保留原指标，新六行放在“传输明细”表。未更改软件位图读回，也未缓存旧屏、改变匹配阈值或删减鉴权。

## 协议和计量边界

- 新可选能力为 `CAPTURE_TRANSFER_TIMINGS`（bit10）和 `CAPTURE_CONTROL_DETAILS`（bit11）；未协商的旧端沿用原帧格式与失败格式。
- 像素数据发送完成后，新端发送同请求身份/认证序列的25字节结束摘要（tag、编码耗时、写出耗时、包数）。单项耗时不超过10秒，包数为1至1093且必须等于实际数据包数。
- 缺失、篡改、错误请求、包数不符、重放、提前出现或截断摘要均作废连接。服务端生成摘要也校验流已完成、包数和数值范围；调用错误必须关闭连接。
- `CAPTURE_CONTROL_UNAVAILABLE` 为固定白名单原因7，只在双方协商后出现；旧端不收到无法理解的新枚举。此错误表示控制通道安全栅栏失效，不是未找到图片。
- 发送封包含像素复制/编码/鉴权等边界工作，写出含等待；发送和接收可能并发。接收读取/校验细分针对像素包，不含结束摘要等待，但总传输时间包含摘要等待。各段及其百分位不能相加。
- `captureTransferUs` 必须完整合法才生成阶段样本；旧记录无字段时不补零。包数按整数显示，不按微秒除1000。

## 发布链路合成基准

设备：Windows x86_64主机，Intel Core Ultra 9 285H，Rust dev配置。合成720×1280 BGRA帧，3,686,400字节；不是识图，ROI和模板尺寸不适用。预热10轮，100轮有效样本，每轮交替两种顺序；仅计所有权转换和帧池发布，像素分配/填充和释放不计时，最近秩 P50/P95/P99。

| 路径 | P50 ms | P95 ms | P99 ms |
| --- | ---: | ---: | ---: |
| 原 Vec→Arc 切片→发布 | 1.0008 | 1.1024 | 1.1737 |
| 移动 Vec→只读共享存储→发布 | 0.0019 | 0.0065 | 0.0100 |

命令：`cargo test -p automation-core benchmark_received_frame_publication --offline -- --ignored --nocapture`。

此对照证明本机发布路径消除了复制成本，不代表 MuMu“帧入池”一定下降相同毫秒数，也不代表整轮截图或找图的收益比例。下一次用户实测需固定720×1280、ROI `[149,407,546,879]`、200×122模板、900‰相似度、容差0及方向0，成功/失败/取消分开，至少100次后比较新旧 P50/P95/P99。
