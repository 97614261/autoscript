# 找图后续优化与全屏日志

日期：2026-10-09。落实用户后续计划及“日志支持全屏、更紧凑”要求。

## 引擎

- 零容差模板预处理保留一个非主色 RGB 粗分桶（4-bit RGB 加透明分类）及四象限主色计数。特征是固定小结构，计入模板资源估算；准备时用固定 8192 桶工作区，无新增依赖、画面缓存或像素副本。
- 主色上下限之后增加辅助颜色桶必要条件和四象限必要条件，均使用整模板允许不匹配数量作为保守界限。辅助桶需有足够频率/预期排除能力且构建预算充足；最多两表合计 8 MiB，超限只禁用辅助表，不扩大上限。
- 非零容差不启用新增桶/象限条件；全透明、无主色、小搜索、严格阈值仍走已有路径。候选顺序、模板优先级、所有评分和多结果重叠/截断不变。停止/截止检查及实际消耗预算继续保留，预算消耗不要求与旧算法数值相同。
- 首候选先精确比较，满足首结果或多结果数量上限则不构表；未满足再构表，从第二候选继续，首候选不重复比较。实测初版辅助表会让首位置找到多付约 0.067 ms 构建成本，已用此路径规避。
- 锚点审查后保留既有四个稀有/高对比点及比较顺序；在允许数千像素不匹配的参数下，额外几个点不能证明失败，不做抽样误判或无收益锚点扩张。以有数学下界的区域条件完成提前排除。
- 截图仍保留上一批已验证的数据路径；本批不取消 GPU→CPU 读回、不绕过鉴权，不以“零拷贝”冒充已测收益。

## UI

- 标题「全屏 / 还原」切换；全屏隐藏重复底部关闭栏，右上角关闭及系统返回保留。共享弹窗新增参数默认不影响其他页面。
- 统计行约 18 dp；结果只在独立表头显示一次，数值维持完整整数/两位小数，单位区分明确。
- 数字详情与参数/解释拆成两层，不用长 ID 和反复说明挤占表格。新增逐事件预筛排除率，不能由计数百分位相除推算。
- 全屏仍支持滚动及大字体，多条件记录不承诺任意内容都能一屏截完。
