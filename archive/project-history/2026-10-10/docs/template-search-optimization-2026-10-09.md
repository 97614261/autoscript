# 找图优化交付：2026-10-09

## 范围与执行

本批落实已确认的五步计划，未运行用户私人脚本；不变更 Lua 参数、项目能力、ROI、模板优先级、搜索方向、步长、评分、透明像素及容差语义。

1. 单模板、模板列表首结果、多结果匹配均接通可关闭的阶段观测：准备/收尾、积分预筛构建、遍历/精确比较，以及模板复用、候选、排除和实际比较像素计数。详情展开显示，旧日志不补零，成功/未找到/取消/超时/预算失败分组独立。
2. safe Rust 比较器按 RGBA/BGRA、零/非零容差、透明策略选择专用路径。保留原锚点比较顺序，之后按连续行段跳过至多四个已比较锚点，移除每像素锚点成员查询；无 unsafe、SIMD 依赖或额外模板像素副本。
3. 复用既有主色积分表增加零容差的非主色必要条件上限。仅排除数学上不可能达标的候选；有容差时不使用新上限，忽略透明时按完整窗口面积计算。积分表启用条件、内存上限、总比较预算及取消/截止仍有界。
4. 截图读回/传输审查完成，本批不改采集数据路径。硬件 Bitmap 转为软件 ARGB_8888 的一次 copy 承担 GPU→CPU 读回，后续 getPixels 保持颜色语义；跨帧只复用有界工作缓冲，不缓存旧画面。认证流式传输仍逐包校验，JNI 的 Vec→Arc 所有权转换仍保留。消除它需要额外内存布局/跨边界设计，不能以未经验证的零拷贝换取颜色或寿命风险。
5. 增加原比较器差分回归、预算/取消观测回归、实际 Lua 三类找图 API 观测测试，以及显式手动合成基准。Android 单元测试验证阶段字段完整性、计数单位、旧记录缺项、结果分组和折叠展示。

准确字段及计时口径见 [运行文件日志](../../../../docs/guides/runtime-file-logs.md)，数学条件见 [ADR 0048](../../../../docs/adr/0048-bounded-fast-root-capture-and-exact-template-prefilter.md)。阶段百分位不可相加。

## 现有设备观测与边界

用户提供的本批优化前截图：MuMu x86_64、HUAWEI DCO-AL00、API 32、720×1280，194 个成功样本，ROI [149,407,546,879]，单模板，相似度 900‰，容差 0。截图 P50/P95/P99 为 31.64/42.75/49.02 ms，找图首结果为 108.45/117.65/122.55 ms；软件位图读回为 12.82/15.85/20.01 ms，帧入池为 1.64/2.24/2.67 ms。模板尺寸需要在新的导出日志复核，不能从旧运行强行继承；这组数据仅定位优先级，不能作为本批已经提升的结论。

此前另一运行的约 319 ms 截图及 327 ms 匹配仅有 9/8 个成功样本，与上述运行时间/条件不同，不混合计算收益。人工停止产生的取消样本不视为找图故障。

## 合成主机基准

Windows x86_64，Intel Core Ultra 9 285H，现有 Rust dev 配置的 pixel-vision opt-level=3，保留 Debug/溢出检查，无并发 Android 构建。每项 100 次，交替先后顺序，最近秩 ceil(N×p)。不含截图、传输、模板加载或设备热状态。这些是 CPU 路径验证，不是 MuMu 或手机承诺。
