# 制作基础字库

`ASGLYPH v1` 用于固定字体的数字、字母和符号识别。它匹配你采样的字形，不是通用 OCR，不需要 OpenCV、ONNX 或训练模型。字体、粗细、描边和界面缩放改变后，应重新采样并测试。

多种文字颜色可直接在制作窗中连续取色，最多16色、每色独立容差，命中任意一种颜色都算文字笔画。不必仅为多色文字先做黑白图；需要排除背景、相对滤色等更复杂规则时，仍可先在截图或图片工作台进行[多组滤色](./image-filters)，再点“制作字库”。

## 在 App 中制作

从可视化编辑器的 **图像 → 字库制作** 直接打开，或在文字分类、**项目设置 → 资源 → 制作字库** 进入。

制作窗按取材、提取、标注、样本和测试分区，操作反馈及保存栏固定底部。样本网格随数量收紧；取样预览下方的工具保持紧凑单行，窄窗或大字体时可横向滑动，不会把缩放按钮拆到下一行。其他内容可滚动，也可从右上角切换全屏，草稿不会重置。放大后的图片、选框及取色放大镜只在预览区域内显示，不遮挡按钮。

1. 选择项目图片或本机图片。需要从其他 App 取材时，使用 **截图取材 → 框选/取色 → 制字**，不用先保存图片或进入处理工作台。截图的选区、已取颜色和容差会带入；原图不缩放、不覆盖。
2. 小图或已有选区会自动放大显示，原图和保存尺寸不变。框选数字区域，切换“取色”点中文字：第一次替换当前色，随后连续取色会追加；重复颜色只选中原色块，不重复添加或改它的容差。点色块可编辑RGB、单独容差，随后取一次色会替换它；“+颜色”用于手动添加，“删除颜色”移除当前色，至少保留一色。未完成、重复或越界颜色会阻止提取与测试，不静默丢弃。工具栏用浅蓝底标识当前模式；“选区”“全图”、加减缩放和“100%”只调整显示，“重选”只清选框。容差按每个RGB通道分别计算，不是灰度阈值。
3. 选择“提取单个”或“按空隙批量切分”。结果按从上到下、从左到右显示，缩略图下方显示序号和标注。可直接点任意字形标一个字，点“应用并下一个”跳到下个未标项；数字、括号、正负号、小数点等快捷键点一下便标注并前进，不需要先填完整批。也可把整行文字粘贴进“顺序字符”，字符数完全一致且不含空白时自动填入；未完成输入须恢复或补齐后才能追加。切页会保留正在输入的标注。重新切分已有待加入批次前需要确认。
4. 误切出噪点时，选中该字形点“移除此字形”，其他字形的标注仍与原字形对应；“撤销移除”可恢复最近一次移除，后续标注或新批次会使该恢复失效。点“追加样本”留在取样页继续补样，或点“追加并测试”。同字符可保留不同字形，精确重复会去重并显示数量；同字形标成不同字符会拒绝。修改未应用时不能追加或切换字形。
5. 样本页用“查找字符”筛选小网格，点选后改标注、删除或修点；搜索不改变样本身份或当前选择，“上一个/下一个”仍按完整样本顺序切换。修点提供画笔、橡皮及自动修点，支持拖动连续描画、放大和移动字形；取消手势不提交，一笔只占一次撤销。自动修点按起点决定补点或擦除，经过同一点不会反复翻转。擦成空字形或造成标注歧义时整笔拒绝，原样本保留。最多12步撤销/重做，当前及历史压紧位图共限8MiB，预算不足时淘汰最早记录。
6. 任意页底部都可“快速测试”。测试调用真实 Rust 字库引擎，不启动脚本；看文本、得分和覆盖率。测试设置页可改相似度、空格列数，空格列数为 `0` 时不插入空格，适合连续数值。可选填“预期文字”，与真实结果逐字完全核对，不影响识别或保存的字库。保存不会清掉测试结果；修改样本、颜色或范围后旧结果失效并提示重测。
7. 输入“字库名称”，点“保存字库”或“保存并识字”。短屏或键盘显示时，名称移到可滚动内容区，保存按钮仍固定在底部。字库自动登记到当前项目；同名时可取消、编号另存或确认覆盖。“保存并识字”打开配置并预选刚保存的字库，带入完整色组、每色容差、相似度和空格列数，不自动加入或运行。已保存且样本、名称未变时复用原字库文件，即使随后调整了色组也不会重复生成文件；新的配置仍须重新测试。

### 按缺采字符连续补样

取样前可点“查看黑白字形”，白色代表当前选区会保留的笔画，改变颜色或容差会更新预览。取色始终读取原图，不会取到预览的黑白色；原图和保存内容不受影响。“像素微调”可按1px移动整框、调整任一边缘，或输入X/Y/宽/高后应用。非法输入保留原选区，不自动截断。

测试结果提供引擎返回的真实逐字框：红框为未识别，橙框为已识别但低于980‰的样本提示，不改变实际识别阈值。点击字框或列表选中，再点“回到取样并框选第…项”，即可在同一原图补样；需填写实际字符，不自动猜标注。参数或样本改变后旧字框失效，须重新测试。

在提取区选择数字、数字符号、大写、小写或符号目标，也可自定义最多128个字符。重复字符仅统计一次，空白不作为采样目标；目标不影响已有样本，也不要求采齐才能保存。

缺采栏直接列出尚无样本的字符。完成当前批次后，点一个缺字，框选实际字形，再点“提取单个”，便会按你的选择预填该字符；核对后追加即可。预填只用于下一次单字取样，多字切分不套用单字标注。“填目标顺序”和“填目标缺字”仅在本批样本数精确对应时出现，仍需核对图中实际顺序；不会自动猜字符或定位字形。

字库文件仍为 `ASGLYPH v1`，只存字形和标注，不存颜色或隐藏滤色。单独另存字库后重开时，应重新选择识别色组；“保存并识字”回填的配置、图像方案和正式识字积木会保留全部色组。颜色调整不会重写已有样本，必要时重新取样。一次识别最多6400万次颜色比较，过大的选区或色组会明确拒绝。

脚本API的旧单色调用不变；`Ocr.glyph` 和 `Ocr.glyphDetails` 可选的最后一个 `additionalColors` 参数使用 `RRGGBB:容差`、分号分隔，最多15项。例如主色红色容差4，再加绿色容差8：`"00FF00:8"`。省略或空字符保持单色。RGB不得与主色或其他附加色重复；可视化会生成旧引擎能力检查，不能在旧引擎上悄悄退化成单色。

截图或工作台中的“保存并识字”继续测试同一张图片，保留制作时的选区；如果制作中另外换了图片，不把新图片的选区带回原图。独立入口打开屏幕识字配置，只带字库和识别参数，须重新确认屏幕范围与已声明输出变量，不能把样本图片坐标当作屏幕坐标。项目设置入口仅保存资源，不提供积木加入操作。

取字配置使用紧凑输入行，范围、字库、颜色、阈值直接可改，长说明按需展开；逐字预览仍保留字框与列表联动。带入字库不等于测试通过，回填按钮仍要求当前参数和运行服务对应的真实测试结果。

图片限 24MiB、单边 4096px、总计 4,194,304 像素；制作限 256 个样本、单字形 256×256px、压紧位图共 2MiB。超限会提示缩小选区，不静默压缩。保存后的资源沿用项目备份与打包流程。

### 固定数字的取样要点

- 优先采样 `0123456789`，需要小数、负数、百分比时补上 `. - %`。
- 数字和小数点尽量放在同一行批量取样，以保留相同的垂直基线。批量按空白行、空白列切分，粘连字形不会被猜测拆开；请重新框选或单独采样。
- 字体描边或渐变可能需要更合适的文字颜色和容差。先看样本中的黑白形状，不要靠降低相似度掩盖错误取样。
- `0/O`、`1/l` 等若在原图中完全相同，字库不能凭空判断语义；只收录实际需要的字符，或在脚本中校验数值范围。
- 制作窗的“测试往返”包含 PNG 编码和传输，不是纯匹配耗时。跨图片、尺寸或设备比较时保持条件一致。

打开项目已有字库会载入可编辑副本；超过制作预算或格式无效时保持原文件不变。未保存的样本关闭前需要确认。

进度栏提示当前目标已采多少，样本页只列当前目标的缺采字符；不要求每个字库收齐62字符。切出26个字形时可以明确选择“填大写”或“填小写”，62个可按数字、大写、小写的顺序填写，仍须核对实际图像。测试不一致时会显示首处差异及缺采字符，预期文字只评分，不会自动标注、猜字或修改识别结果。只有当前样本、字形及保存名称对应同一次保存结果时，“保存并识字”才复用已有资源；撤销回到已保存版本也可复用。重新打开字库副本会清空本次撤销/重做历史。

## 制作命令

也可使用仓库中的命令行工具。字形源用 `#` 表示前景、`.` 表示背景；工具裁掉外围空白，输出运行字库和独立 HTML 预览。

在仓库的 `rust` 目录运行：

```powershell
cargo run --offline -p glyph-maker -- tools/glyph-maker/examples/basic.json ../build/main.asglyph ../build/glyph-preview.html
```

输出文件存在时工具会拒绝覆盖。请换用新的输出名称，不要覆盖自己正在使用的字库。

## 项目声明

把生成字库作为项目资源登记：

```json
{
  "kind": "glyphDictionary",
  "path": "dictionaries/main.asglyph"
}
```

资源必须实际存在并通过校验。下面是运行接口的调用示意，不是可直接导入的积木源码：

```lua
local frame = Screen.cache(Screen.capture())
local dictionary = Ocr.loadDictionary("dictionaries/main.asglyph")
local result = Ocr.glyph(frame, dictionary, 0xffffff, 20, 850, 0, 0, 720, 1280, 3)
Ocr.releaseDictionary(dictionary)
Screen.release(frame)
```

## 检查结果

结果包括 `text`、`coveragePermille` 和 `averageScorePermille`。不要只检查文本非空；应结合未知字形和覆盖率判断识别是否有效。需要定位时查看逐字结果及文字查找接口。

相关 API：[`Ocr.loadDictionary`](/api/generated/ocr/load-dictionary)、[`Ocr.glyph`](/api/generated/ocr/glyph)、[`Ocr.glyphDetails`](/api/generated/ocr/glyph-details)、[`Ocr.findText`](/api/generated/ocr/find-text)。
