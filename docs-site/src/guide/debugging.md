# 调试与运行日志

用单步确认行为，用运行高亮定位流程，用日志分析失败。不要把“请求已提交”当成积木已经成功执行。

## 单步与运行高亮

空闲单步只执行选中积木及其子树；暂停单步推进当前脚本。运行高亮跟随真实执行节点，与编辑选中状态和日志开关分离。短时间经过的节点也可能只短暂出现，不会为了动画延迟脚本。

## 三类输出

| 输出 | 用途 |
| --- | --- |
| 脚本日志 | 脚本主动输出给编写者的消息。 |
| 诊断日志 | 连接、Runner、Root 和运行状态。 |
| 结构化事件 | 可选的执行追踪和识图耗时等观测。 |

运行提示与短时弹窗是给使用脚本的人看的 UI，不是诊断日志。提示总开关在项目设置；提示样式在调试中配置；执行追踪和识图统计在日志记录设置中配置。

“运行提示”更新同一窗口，脚本正常结束时即关闭。识别数字后马上打印并结束，可能来不及看到。
这种最终结果请选择“弹出提示”，正常结束后会保留至设定时长；主动停止仍关闭提示。
可用表达式“名称=值”查看识别结果是否为空，并确认项目的提示总开关已开启；不需要额外加等待。

“变量值”和“名称=值”按变量类型自动插入：字符串直接使用，整数/浮点只在输出时包裹 `text(...)`，不改变变量本身。
例如字符串变量「识别文本」保存 `+190`，快捷生成 `"识别文本=" .. 识别文本`，显示 `识别文本=+190`。
需要参与计算时，再用变量计算的 `int(识别文本)` / `float(识别文本)` 写入数值变量；单纯打印不需要转成数字。

提示样式和项目运行设置中的位置区共用九宫格快捷：左上、上中、右上、左中、居中、右中、左下、下中、右下。点击只修改待保存的 X/Y，按当前屏幕像素和当前填写的宽高计算；居中轴使用 `-1`，仍可手动微调。修改尺寸或切换横竖屏后可以重新点选位置，确认后保存；已保存坐标不会自动随方向改写。

## 排查识图耗时

区分截图采集、传输、帧准备和匹配。匹配区变小可以减少搜索工作，但不能解决截图采集本身失败。

比较记录时，应保持设备、分辨率、ROI、模板尺寸与算法一致。独立阶段的 P95/P99 不能相加当作端到端百分位；一次快结果也不能证明所有业务稳定低于某个时长。

## 保存和清理

运行记录保存在 App 私有日志目录，可从日志界面查看和导出。日志清理需要确认，只处理选中的运行记录，运行中、待写完和未知文件会保留，不删除项目、图片或已导出的文件。

日志不自动记录完整脚本、变量值或模板路径。你主动调用日志 API 输出的内容由你决定，避免把密码或其他敏感数据写入消息。

## 未运行脚本时的截图失败

从「我的 → 运行环境 → Root / 截图诊断」打开并复制详情。这个入口始终保留，不必先运行脚本或等待错误提示。App诊断单独有界落盘，可区分截图超时、采集进程启动、管道读取、传输和无效帧等固定错误码；不记录原始进程输出或截图内容。

Root已验证不代表截图采集成功。触点清理无法确认时仍禁止继续输入，作废旧连接并走有界重连；不会重放刚才失败的点击。ARM设备的具体失败原因仍需该设备新日志确认。
