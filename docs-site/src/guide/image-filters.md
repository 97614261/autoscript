# 滤色找图与字库取材

滤色按颜色规则保留目标、排除背景，输出黑白图或带透明区域的原色图。它与灰度、灰度阈值二值化是不同处理，不会自动替换既有找图算法。

## 操作流程

1. 在图像工具截图后点 **滤色**，或从图片库进入 **图片工作台 → 滤色**。原图保留，预览及保存不缩放像素。
2. 轻点预览取原图颜色，或输入六位 RGB。分别填写 R、G、B 容差，范围 `0–255`；多种目标颜色点“加颜色”，背景颜色可切为“排除该颜色”。排除规则优先。
3. 选择“黑白输出”或“透明保留”，在原图与滤色图间对照。预览取色始终读取原图，不会把处理后的白色误当原字体颜色。输入无效时不能应用或保存成方案。
4. 需要复用时，填写方案名并“另存方案”；同名生成副本，不覆盖原方案。载入未应用规则前确认替换，删除方案需要确认。方案随项目备份、恢复，不随运行改变。
5. 点“应用滤色”进入处理历史，可撤销、重做、另存新图片、找图测试、取字测试或制作字库。加入处理积木会复制完整规则，明确选择已声明的中间帧和结果帧变量，中间帧按既有流程释放。

小窗预览固定顶部，规则与方案区独立滚动；右上角可以放大，草稿和非法输入均保留。关闭未应用规则会确认；已保存方案不因关闭丢失。

## 三种匹配方式

- **绝对滤色**：每个 RGB 通道分别与目标颜色比较，误差不超过该通道容差。
- **相对滤色**：比较 `R−G`、`R−B`、`G−B`；每项允许误差是对应两通道容差之和。共同增加或减少 RGB 的明暗变化不影响判断，因此不能用它区分纯灰色的深浅。
- **自定义滤色**：每条规则独立选绝对或相对方式，混合保留和排除颜色。

多条保留规则取并集，任一排除规则命中即排除。只有排除规则时，默认保留其他不透明像素。“反选”在规则判断后取反，原本完全透明的像素始终不变成可见像素。

黑白输出保留源 Alpha，命中写白、未命中写黑；透明保留输出原 RGBA，未保留像素清为完全透明。

## 用于找图

**透明模板**：将需要比较的图案滤色为“透明保留”，另存为新 PNG 模板。普通像素找图会忽略模板的完全透明像素，不要求先处理屏幕背景。模板剩余部分仍按原色与容差匹配。

**黑白形状匹配**：模板和待识别画面都应使用预期的滤色规则。先保存处理后的模板，再对运行截图应用滤色；在工作台“找图测试”验证，选择加入“处理＋找图”。不会暗中处理一张原色模板，也不会对处理图自动点击。

规则保留尺寸和坐标，但后续裁剪、旋转、缩放可能改变坐标关系；处理图坐标不能直接当作原屏点击坐标。

## 用于字库

滤色后在工作台点“制作字库”，以白色前景采样黑白图，完成显式标注、保存和真实 Rust 测试。字库仍为 `ASGLYPH v1`，不把滤色配置藏进字库文件。运行识字也应对图像应用同样的滤色，并将处理后的图像变量传给字库识字积木；工作台可在测试后加入完整处理和取字链路。

参见[制作基础字库](./glyph-dictionary)和[图像与文字识别](./vision)。

## 预算与兼容

每次滤色最多32条规则、8192字节规则 JSON、4,194,304像素及6400万像素规则比较；超限拒绝，不截断规则或降低图片分辨率。每个项目最多32个方案，配置文件共128KiB；损坏文件不被空列表覆盖。运行使用加入时复制的配置，修改或删除方案不改变已有积木。

底层复用 [`Screen.transform`](/api/generated/screen/transform) 的 `mode="filter"`。规则语义是智构明确的版本1契约，不声称与不可见的旧 Native 实现逐项等价；旧运行包不认识该模式时应报错，不回退灰度。
