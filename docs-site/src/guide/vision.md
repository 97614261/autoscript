# 图像与文字识别

识别先准备输入，再测试参数，最后加入积木。优先裁剪有辨识度的模板，并使用足够但不过大的搜索区域。

## 从截图到识别

1. 从图像工具打开截图或图片库，明确操作的项目和插件。
2. 裁剪模板，选择保存文件夹；可以新建文件夹、改名。保存保留原像素，不静默缩放模板。
3. 选择找图、颜色或文字识别，填写区域、阈值和已声明的输出变量。
4. 在当前图像上测试，再选择行前、行后、子区或底部加入。测试命中不保证下一帧也命中。

## 找图成功与失败分支

区域找图、灰度找图和多结果找图支持成功 / 失败两个分支。加入积木后，点选对应分支标题，再从函数或图像工具加入操作；空分支可以不放操作。识别完成后，找到执行成功分支，没找到执行失败分支，随后继续后面的积木。

截图、识别报错或取消会中止当前执行，不当成“没找到”。设置识别频次时，跳过的轮次不执行任一分支。原有“找到后动作”仍会先执行，再进入成功分支，避免在两处重复配置同一点击。

旧的区域找图或灰度找图仍可直接运行；要使用新分支，打开该积木参数并保存一次，便会补出两个空分支，不删除或替换已有操作。

## 算法各有边界

| 类别 | 适用范围 | 注意 |
| --- | --- | --- |
| 原像素找图 | 声明的图片模板，像素容差和相似度。 | 多模板次序有语义；搜索预算和方向按接口约定。 |
| OpenCV 灰度找图 | 单模板的灰度匹配。 | 不自动缩放或旋转，分数不能与原像素算法等同。 |
| 找色与多点找色 | 单点颜色、相对颜色模式、连通块。 | 颜色容差、采样位置与搜索区域分别设置。 |
| 字库识别 | 自制固定字体及字形。 | 看覆盖率和逐字结果，未知占位符不算有效识别。 |
| ONNX 字母数字 | 指定单行 ROI 中的英文、数字；开启保留符号可识别常见 ASCII 符号及空格。 | 不包含中文或通用文本检测，`l/1` 等相似字形仍可能混淆。 |

## 找色支持多个备选颜色

找色、比色、颜色计数和查找全部颜色可在「匹配色组」中添加颜色，最多16色，每色单独设0–255容差。点色块选择要修改的颜色，再手填RGB或屏幕取色；保存色组后回填配置。任意一种颜色符合即命中，同一像素只计数或返回一次。

这与「多点找色」不同：备选色组在同一位置匹配任意颜色；多点找色要求各偏移位置分别符合配置。单色脚本不必改动，非空备选色组需要 runtimeApi 1.8，正式保存和运行草稿会按原规则提升版本。

Lua API 的最后一个参数可写 `additionalColors`，格式为 `RRGGBB:容差;RRGGBB:容差`。例如 `Screen.countColor(frame, 0xFF0000, 8, 0, 0, 720, 1280, 0, "0000FF:16;00FF00:0")` 统计指定区域内红、蓝、绿任一命中的全部像素；容差重叠不重复计算。留空或省略色组参数保留原单色行为。示例使用已有帧，帧的采集与释放仍由调用方负责。

颜色计数默认「统计全部」，不设匹配数量上限。仅需判断是否达到某个数量时，勾选「提前停止」，填写1–6400万的阈值；旧积木保存的正数上限保持原值。计数是像素数量，不是物体数量。Lua 的数量参数 `0` 表示统计全部，`0` 或大于256需要 `Screen.colorLimitsVersion == 1`，可视化项目按原流程提升到 runtimeApi 1.8。

「全部找色」需要保存坐标列表，可设置1–2048个坐标，按搜索顺序达到数量即停止；文本输出使用 `COLORS` JSON，可通过「读取识别结果属性」读取数量或第1–2048项位置。它与只返回一个整数的颜色计数不同，不能用截断后的坐标列表长度代替全区域计数。批量多点找色和颜色连通块仍各保留原来的256项限制。所有查询仍受图像尺寸、比较次数及取消边界约束，超预算会报错。

简单颜色配置使用单页，参数与输出集中显示；说明点击展开，短屏可滚动查看全部输入项。模板/OCR等复杂配置保留分区和全屏切换。

## 自动识别符号并分别取数

不需要制作字库。在「图像 → 文字 → 字母 / 数字 / 符号」中选择单行区域，开启「保留符号」，把全文写入已声明的文本变量，例如「识别文本」。可保留模型识别出的 `()`、`+`、`-`、`.`、`%`、`/`、`[]` 和空格；不会自动补出漏识别的字符。该模式使用原有 V4 模型，需要内置 ONNX 或 V3 组件，旧组件会明确提示不兼容。

从「图像 → 文字 → 文本处理」选择「正则提取全部」，来源选择「识别文本」，常用规则选择「数字（含正负号、小数）」，把结果写入一个文本变量。若全文为 `100(+100) 180`，结果是 JSON 文本列表 `["100","+100","180"]`。选择「正则提取首项」则直接得到文本 `100`；无匹配时，全部模式返回 `[]`，首项模式返回空文本。

这套文本处理不绑定 OCR 或特定变量名：手写文本、识别结果、文件内容和接口返回都可以输入。支持数字、连续数字、英文字母、字母与数字、中文、按空白分开的内容等规则，也可以自填正则或从文本变量读取规则；另有按两侧标记取文、分隔和替换。函数库的「文本」分类也能加入同样的积木，不会重新截图或执行 OCR。

### 在函数库使用正则

打开「函数 → 文本 → 正则」，可直接加入匹配判断、提取首项、提取全部或正则替换。四项均可选择常用规则、自定义表达式或规则变量。正则按原样输入，例如 `\d+`、`[A-Za-z]+`、`\p{Han}+`；在参数输入框中不需要再多写一个反斜杠。

匹配判断在文本任意位置命中时写入整数 `1`，未命中为 `0`；要求整段符合规则时可写 `^[0-9]+$`。提取结果为完整匹配；替换将全部命中换成填写的字面文字，`$1` 等不会展开。支持分组、字符类和重复，不支持环视、反向引用或单独输出捕获组。

需要逐项读出列表时，用「函数 → 集合 → 取集合 / 对象标量」，来源选择结果列表，索引从 `1` 开始；字符串结果再交给「解码 JSON 字符串」得到不带 JSON 引号的文本。读取前可用集合长度判断是否有对应项，避免把没有结果当成数值零。

已有 `Text.numberAt` /「按序提取数字」仍可使用：来源是任意文本，序号从 `1` 开始，无该项返回空文本。数字规则保留紧邻正负号、前导零和小数位，不计算表达式，也不转换百分比、千分位或科学计数法。正则提取与按序取数的输入最多 4096 UTF-8 字节、最多 64 项；需要计算时再显式转换为数值。

查看脚本结束后的结果请用「弹出提示」；「运行提示」随脚本结束关闭。旧识别积木默认仍只输出字母数字，需编辑参数开启保留符号。

## 一帧可以做多次查询

区域找色、多点找色、颜色计数和查找全部颜色使用实际输入帧的像素范围。若取样时横屏、运行时竖屏等原因导致合法非空范围越界，本次按未命中处理：找色为未找到、计数为 `0`、全部颜色为空列表，脚本继续。日志说明请求范围和实际截图尺寸，同一任务内相同位置与范围的提示会去重；不自动缩放、旋转或裁剪到别处识别。负坐标、空或反向范围、无效图像及其他错误仍需修正。

新生成的可视化脚本在运行错误与上述警告中显示插件名称、积木行号、函数类型及节点 ID。行号按运行版本中插件的积木顺序计算，包含子积木和注释行，折叠不改变编号；它与错误详情里的生成 Lua 行号不同。直接执行 Lua 源码或旧生成物没有积木行号时，保留原有诊断信息。

「图像」菜单的「新积木默认」可选择「每次截图」或「共用图像」，会记住这台设备的选择。每项识别配置顶部也可单独选择；默认选项只影响从图像工具新建的识别，不改变已有积木或处理工作台的输入。

- **每次截图**：每次实际识别时重新采集，识别后自动释放本次帧；不会用旧截图代替新画面。取色、找色、比色、多点找色、颜色计数和全部找色使用内部临时帧，不需要先声明截图变量。其他需要可见截图/识别/释放组合的操作，仍须选择已声明的专用图像变量，并确认允许覆盖、释放。
- **共用图像**：选择已声明的来源图像变量，不重新截图、不自动释放。可以先加入一次「获取全屏帧」，连续找色、找图和识字，最后加入「释放图像帧」。点击、滑动或等待画面变化后，需重新截图才能识别新画面。

取色、找色、多点找色、普通/灰度/多结果/多尺度/特征找图以及字库、V4、V5识字入口共用以上选择。结果读取和图像处理仍读取明确指定的结果或图像，不随默认设置偷偷截图。已有的共用帧积木保持原来的截图、释放步骤；只有自身支持自动截图的积木，才能在编辑单个积木时直接切换。

同一轮中明确持有缓存帧时，可以在该帧上做多项识别，减少重复截图。自动截图表示查询时获取新输入，不能把旧缓存屏幕假装成新帧。帧释放责任以[能力与资源约定](./contracts)和每项 API 为准。

## 处理图与原屏不同

工作台可处理灰度、旋转、镜像、裁剪和缩放，处理结果独立于原图。识别尾部读取处理后的帧，不隐式再截图；处理图中的位置不能直接作为原屏点击位置。

工作台还提供蒙版、数字清理、完整图像方案、多尺度找图、候选差异和有来源约束的坐标还原，详见[蒙版、清理与稳定识别](./image-workbench)。

等待识别出现、消失或超时，使用界面提供的可见循环和判断组合；工作变量要先声明，不隐藏创建。
