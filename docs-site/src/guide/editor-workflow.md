# 插件、分支与连续编辑

插件是项目中的独立流程文件，主插件是项目入口。一个项目可以有多个插件及虚拟分组；分组不是运行顺序，也不是图片文件夹。

新项目和新插件从空白开始，不自动添加空任务；历史项目已有的空任务保留。空插件自然结束，返回成功。

变量、插件参数和跳转标签支持汉字、英文字母及下划线开头，后续还可用数字，最多64字符。名称作为精确键保存，不自动拼音化；例如 `剩余次数 - 1` 可以直接用于变量计算。项目名、插件文件名和分组原本即可中文命名。自动生成的ID、控件ID及API函数名保持原规则，不改协议身份。

## 给成功、失败分支加入操作

1. 先创建被调用插件，在其中写好独立功能。
2. 回到调用方，加入插件调用，并选择被调用插件。
3. 点击调用下面的「成功」或「失败」标题，把该分支选为加入位置。空分支也可以点，不需要先放占位积木。
4. 打开按键、图像、调试或函数配置，填写参数，再加入。普通加入沿用已选分支；若出现位置确认，选择对应真实子区，不要误选调用后的普通下一行。
5. 在另一分支重复操作。两个分支可以分别放日志、提示或其他处理。

示例：主插件调用「检查页面」。它返回成功时执行「点击进入」，返回失败时执行「弹出提示：请先打开目标页面」。调用的后续普通积木位于两个分支之外，不等于成功分支。

## 谁决定成功与失败

在**被调用插件**中使用「返回成功」或「返回失败」。自然运行到末尾默认成功。调用方按实际返回值选择分支；运行异常、用户停止与取消是中止，不应靠失败分支吞掉。

「成功/失败」标题只是加入位置，不是可执行积木。空闲单步、删除或复制时，要选择实际操作行，不能把分支标题当成所属调用行。

## 参数窗何时关闭

| 页面 | 完成后的行为 |
| --- | --- |
| 单项参数窗 | 实际加入草稿后关闭，选中并定位新积木。 |
| 加入位置选择 | 取消会回到原参数，不丢输入，也没有提前加入。 |
| 函数库、图片处理工作台 | 保留，方便继续选其他操作；单项参数仍按上一条处理。 |
| 底部编辑操作窗 | 保持打开，可连续复制、粘贴、修改、撤销等。 |

加入草稿不等于已经保存正式项目；正式运行前仍需保存与校验。切换插件、修改草稿或运行状态变化可能使旧请求失效，此时保留参数，重新选择位置，不会偷偷写入另一个插件。

## 插入与撤销

可以选择本行之前、本行之后、真实子区或列表底部。前插保留原森林顺序与子树；图像组合整体加入后一次撤销，不需要逐行拆除。

底部编辑窗支持多选与折叠子积木，折叠只改变显示。父积木「注释执行」会跳过整棵子树；恢复父级不会清掉子行原本单独设置的禁用状态。显示别名只改变说明，不改变执行参数。

## AI 助手

文字生成、修改所选积木和报错分析见 [AI 助手](./ai-assistant)。AI 方案先预览、整项目校验，再确认应用到草稿，可撤销；不会自动运行。

## 单步没有执行时

先选实际积木行，再检查变量、项目能力及 Root 实际特性。空闲单步不会执行前置赋值，因此需要先准备本行依赖。分支标题不能单步。详情见[调试与运行日志](./debugging)。

空闲单步不显示自动「插件运行/插件返回」提示，显式提示积木仍可预览；完整运行仍按项目设置中各自动提示分类执行，不修改已有选择。
