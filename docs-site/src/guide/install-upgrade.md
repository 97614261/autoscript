# 安装、升级与备份

下载入口在独立[下载页](/download)。可选单架构 Release 优化候选，以及保留的双架构 Debug 开发包。它们均使用开发证书，不是商店正式发行版，也不是免 Root 自动化工具。

## 安装前

1. 选择适合设备架构的包：大多数安卓手机用 **ARM64**，MuMu 的 x86_64 实例用 **x86_64**；模拟器也应先确认实际架构。历史双架构 Debug 包保留作回溯。
2. 核对页面的版本、构建日期、大小及 SHA-256。开发包可能使用相同版本号，日期与摘要用来区分实际内容。
3. 只在信任来源时允许浏览器或文件管理器安装未知应用。HTTP 下载不能证明来源身份，校验值应通过可信渠道另行确认。

Windows 文件校验：

```powershell
Get-FileHash -Algorithm SHA256 .\下载的安装包.apk
```

SHA-256 证明文件内容与所核对摘要一致，不代替签名来源或 HTTPS 身份认证。

## 优化候选与开发包的区别

优化候选按架构拆分，并使用 R8、资源及原生编译优化；**不删除识图、OCR 或其他脚本能力**。完整视觉配置、默认 V4 与显式可选 V5 均保留。候选与既有开发包包名和签名证书相同，不能同时安装。首批候选为 `0.1.0 / 1`；手动更新为 `0.1.1 / 2`，App 内自动检查及下载从 `0.1.2 / 3` 开始，以下载页所选 APK 的实际字段为准，同版本构建仍用完整摘要区分。

候选已完成主机测试、签名和包结构检查，**尚未完成该候选 APK 的设备验收**；旧 Debug 包的 MuMu 结果不能当作优化候选通过。重要脚本先备份，再在自有项目中确认安装、启动、悬浮编辑、Root 输入、识图和停止流程。

## 升级前先备份

Studio `0.1.2`（版本代码 `3`）起，打开 App 会自动检查更新；可在「我的 → 关于智构 → 应用更新」关闭自动检查或立即手动检查。
只读取站点当前版本和对应架构候选，不从历史列表推荐升级；同版本代码不冒充新版。
确认后在 App 内下载并核对摘要、实际版本和当前 App 签名，再由 Android 系统确认安装；不静默安装或清除项目。
更早版本需先手动安装一次。站点若尚未发布比当前 App 更新的版本，会显示站点较旧；这不代表检查失败。完整操作见 [App 内更新](/guide/app-update)。

「更新地址」可设置文档站根地址。HTTPS 优先；HTTP 未加密，使用前需确认来源可信。
安装前仍需核对可信来源和签名，网页上的摘要与签名文字本身不构成真实性证明。

在「项目」或「我的」中使用真实备份入口，导出重要工程，确认文件已保存到 App 外的位置。升级优先覆盖安装，保留现有数据；不要因为安装失败就卸载或清数据。

项目备份包含正式项目、插件、声明资源、变量、界面及受支持的组织信息。未提交参数、编辑器恢复记录和运行日志不等于项目备份；要保留排错记录，应另外从日志窗导出。

个人服务器手动上传及恢复见[服务器项目备份](./server-backup)。需要独立部署备份服务和保管个人密钥，不复用 APK 发布密钥；恢复始终为新项目。

| 安装问题 | 应怎样处理 |
| --- | --- |
| 签名不一致 | 停止覆盖安装，核对来源和原签名，先导出旧项目。 |
| 系统阻止降级 | 不强制卸载，先确认数据兼容与备份；历史包不保证能读取新版数据。 |
| 下载不完整或摘要不符 | 不安装，重新获取并核对完整文件。 |
| 安装成功但按键不能用 | 到「我的」检查系统授权、连接、Root 就绪及实际输入特性，四者不能互相代替。 |

## 首次打开

按明确提示授予所需系统权限。悬浮编辑需要系统悬浮授权；Root 由设备环境提供，不会因勾选项目能力自动获得。不要为了运行脚本开启不相关的权限。

新建项目后先用[第一个自动化项目](./quick-start)中的无触摸提示验证流程，再在自有测试页面验证截图与输入。使用插件调用见[插件与分支](./editor-workflow)。

## 版本说明

[更新记录](/releases/)只说明已完成的有限批次，不把构建成功或模拟器验收当作所有真机、所有参数组合均已通过。网站回滚只影响网页和下载内容，不自动降级手机中的 App。
